# 範囲

範囲を値として扱う組み込み型 `range^` です。「未決事項」は未実装です。

## 方針

範囲を組み込み型 `range^<T>` の値とし、`a .. b` と `a to^ b` をそのリテラル構築子とします。
添字はその値を受け取る一つの場所にすぎなくなり、同じ範囲を関数の引数にも渡せます。

```rhat
let^head = 0 .. 3
let^tail = (3 ..)
print^(xs[head], xs[tail])
let^part = s.slice(1 .. 4)
let^pick = f^xs:i64^[..], r:range^-> i64^[..] { xs[r] }
```

Rust の `a..b`（`Range<T>` の値で、添字・スライス・反復に同じ値を渡す）や Swift の `a..<b` と同じ位置づけです。

`a .. b`・`a to^ b` は最も弱く結合し、境界には任意の式を書けます（`i + 1 .. n * 2`）。
ループの見出し（`for^ i from^ 1 to^ 10`）と値マッチの腕（`when^ 1 to^ 3:`）の `to^` は、それぞれの構文のもので範囲ではありません。
添字の中に書いた範囲のリテラル（`xs[1 .. 3]`）は値を作らず、今までどおり境界を直接使うスライスになります。

## 要素型

`range^<T>` の `T` は境界の型です。`T` に使えるのは `i64^` に収まる整数（`i8^`〜`i64^`、`u8^`〜`u32^`）です。
`u64^` や128ビット整数の数え上げには `from^` を使います。

```rhat
let^n = 2
let^big:i64^ = 2
0 .. n          # range^<i32^>
0 .. big        # range^<i64^>
0 .. xs.len     # range^<i64^>
0 .. 5          # range^<i32^>。リテラルの既定どおり
n .. big        # 誤り: 算術と同じく混在できない
```

型が付いた境界が要素型を決め、リテラルはそれに揃います。期待される型が `range^<T>` なら、その `T` に揃います。

## 頂点型 range^

型引数のない `range^` は、すべての `range^<T>` の頂点型です。`range^<T>` はどれも `range^` に暗黙に渡せます。
`i32^` を `i32^ | nil^` に渡すのと同じ、上位の型への変換で、数値の暗黙変換ではありません。

```rhat
let^len = f^r:range^ -> i64^ { r.len }
len(0 .. n)                # range^<i32^> を渡せる
len(0 .. 5000000000)       # 期待される型が range^ なので、リテラルだけの範囲は i64^
let^top:range^ = 0 .. n
print^(top.start)          # i64^
```

- `range^` の境界は `i64^` として読みます。`T` はどれも `i64^` に収まるので値を失いません。
- 逆向きの変換はありません。実行時に `T` を持たないので、`range^` を `range^<i32^>` に戻すことも、
  `fits^` で動的に確かめることもできません。`fits^` は静的な型で答えます。
- 添字の `xs[r]` と `s.slice(r)` は `range^` を受け取るので、どの `range^<T>` も渡せます。
  スカラーの添字 `xs[i]` が `i32^` を受け取るのと同じです。`xs[a .. b]` の境界も、`i64^` に収まる整数なら受け取ります。

## 値

- どの要素型でも `{ start:i64^, end:i64^ }` の半開区間 `[start, end)` です。`T` は型の上だけの区別で、表現は共通です。
  16 バイトで、LLVM の値のまま受け渡します。`range^<T>` から `range^` への変換は実行時に何もしません。
- 要素型ごとに `T` の幅で持つと、開いた範囲の番兵が `u8^` の `0 .. 0` などと衝突し、`len`・`contains`・スライスの処理も型ごとに必要になるので採りませんでした。
- `a .. b` は `{a, b}`、`a to^ b` は `{a, b + 1}` です。`b` が `T` の最大値なら範囲外として扱います（後述）。
- 始端を省略すると `0` です。
- 終端を省略した範囲は「最後まで」を表す開いた範囲です。終端には番兵値（`i64^` の最小値）を入れ、受け手が長さで閉じます。
  明示した終端が長さを超えれば範囲外ですが、開いた終端は常に長さに閉じるので、両者は区別されます。
- `start > end` の範囲は空です（`3 to^ 2` は数えるループの空範囲と同じ）。負の値も値としては持てます。
  添字に使ったときに、負の開始・長さを超える終端を実行時に診断します。

### メンバー

`T` は `range^<T>` の要素型で、`range^` では `i64^` です。

- `r.start:T`
- `r.end:T | nil^`: 開いた範囲なら `nil^`。
- `r.len:i64^`: 要素数 `max(end - start, 0)`。開いた範囲では終了します（長さが決まらないため）。
- `r.contains(i:T) -> bool^`

メンバーはすべてコンパイラの組み込みで読み取り専用です。`r.start := 1` のような代入はできません。
`range^{...}` のような構築は書けず、範囲は `..`・`to^` で作ります。
`to^` の終端が `T` の最大値なら、半開区間の終端を `T` で表せないため「the end of a to^ range overflows」で終了します。
`u8^` の 0 から 255 までを数えるときは `from^` を使います。

## 端の省略と区切り記号

R^ の文は改行で区切らないため、端を省略した `..` の後ろに次の行の式が続くと終端として読まれてしまいます。

```rhat
let^range = 0 ..
print^(range)       # 0 .. print^(range) と読めてしまう
```

そこで、省略した端の側が区切り記号であることを構文の条件にします。

- 終端を省略できるのは、`..` の直後が `)`・`]`・`,` のときだけ。
- 始端を省略できるのは、`..` の直前が `(`・`[`・`,` のときだけ。
- 両端を省略した `..` は、両側が区切り記号のときだけ。

```rhat
let^r = 0 ..          # 誤り: 端を省略した範囲は括弧かブラケットの中に書く
let^r = (0 ..)        # よい
let^all = (..)        # よい
xs[2 ..]              # よい（今と同じ）
s.slice(0 ..)         # よい: 引数の括弧が閉じている
f(.. 3, x)            # よい: ( と , が区切る
```

`(0 ..)` の括弧は普通のまとまりの括弧で、`)` が直後に来るから省略できるというだけです。
両端を書いた範囲 `0 .. n` はどこにでも書けます。`to^` は今までどおり両端が必要です。

## 範囲を受け取る場所

- 添字: `xs[r]`。固定長配列・伸長配列・スライスでは要素の範囲、ビュー `T[..]` を作ります。
  `xs[a .. b]` は、添字の中に範囲のリテラルを書いた形として今と同じ意味です。
- 関数・メソッドの引数: `range^` や `range^<T>` の引数として普通に渡します。
- 文字列: `s.slice(r)` はバイト範囲で、結果は `string^` のビューです（[文字列と文字](strings.md)）。`string^` は `[]` を持ちません。
- 反復: `for^ i in^ 範囲` は `range^` の値を始端から一つずつ回します（次節）。

## 反復

```rhat
for^i in^0 .. 3 { print^(i) }        # 0 1 2
for^i in^1 to^3 { print^(i) }        # 1 2 3
for^i in^0 .. xs.len { print^(xs[i]) }
for^i in^r { print^(i) }             # r:range^
for^i in^(5 ..) { ... }              # 上限のない数え上げ
```

`in^` の右辺は常に `range^` の値です。リテラルも変数も関数の結果も同じ規則に従います。

- 焦点 `i` の型は範囲の要素型で、読み取り専用です。`n:i32^` なら `for^i in^0 .. n` の `i` は `i32^`、
  `range^` の値を回すときは `i64^` です。範囲の式は開始時に一度だけ評価します。
- `start >= end` の範囲は一度も回りません。`first^`・`last^` などの節は他のループと同じです。
- 見出しでも端の省略の規則は変えません。開いた範囲は `(5 ..)` と括弧で書きます。
- 範囲以外の `for^ x in^` は[文法](syntax.md)の「反復の約束」を参照してください。

`in^` と数えるループ `for^ i from^ 1 to^ 10` は別の形として残します。
`in^` は「範囲の値を順に回す」だけを担い、次のものは `from^` を使います。

- 焦点の型の注釈（`for^ i:u8^ from^ 0 to^ 9`）と、`u64^`・128ビット整数の数え上げ。
- `T` の最大値までの数え上げ（`u8^` の 0 から 255 まで）。
- `step^` と `downto^`。範囲の値には刻み幅も向きもないためです。

数えるループの構文の別表記にすると、`for^ i in^ 0 .. n` と `let^r = 0 .. n` で
受け付ける型や焦点の型が変わるので採りませんでした。実数の範囲は持ちません。

## 未決事項

- 静的に決まる範囲違反のコンパイル時検出: 定数境界の負値・逆順（`a[2 .. 1]`）や、
  固定長配列・文字列リテラルの長さを超える終端を、実行時ではなくコンパイル時に診断するか。
- 片側省略を `to^` にも認めるか（`(3 to^)` など）。
- 刻み幅 `step^`: 数えるループと同じ語で `n to^ m step^ 3` / `n .. m step^ 3` と書く。
  スライスでは要素が連続しないため、ビューに刻み幅を足すか、刻み付きビューを別の型にするかを決める必要がある。
  範囲の値にも刻み幅を持たせると 16 バイトを超える。
- 逆順 `downto^`: `n downto^ m` を範囲・スライスに認めるか。スライスでは逆順のビューになり、`step^` と同じく表現の拡張が必要。
- 整数以外の範囲（`char^"a" .. char^"z"` など）を持つか。
