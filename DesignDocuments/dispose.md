# 資源の解放 Disposable

`Disposable` を合成した型の値は、スコープを抜けるときに `dispose` が呼ばれます。Rust の `Drop` に相当します。
`Disposable` は標準ライブラリの `std.disposable` にあり、import なしで書けます。

```rhat
def^Device : Disposable {
    self^{ private^raw:i64^ }
    dispose = p^self^ { rh_device_close(self^.raw) }
}

let^use = p^path:string^ -> nil^ | Error {
    var^device = try^open(path)      # どの経路で抜けても dispose される
    try^device.write("x".bytes)
    return^nil^
}
```

## L^ の with^ を採らない理由

L^ の `with^` は、GC の下で解放の時期を決められないために必要な構文です。
R^ の値の寿命はもともとスコープで決まり、`return^`・`break^`・`next^`・`try^` を含む全経路の後始末もコンパイラにあります。
別の構文を足す理由がないので、`with^` は採りません。

スコープを短くしたいときは `do^{...}` で区切ります。

## 規則

### 解放の時期

- 束縛（`let^`・`var^`・`_^`）はスコープの終わりに、宣言の逆順で解放します。ループの束縛は周ごとです。
- 値が持つものも解放します。順序は「自身の `dispose` → フィールドを逆順に」です。配列は要素を逆順に、合併は入っている選択肢だけを解放します。
- `a := b` は新しい値を評価してから古い値を解放します。
- `clear`・`truncate` は取り除く要素を解放します。`pop` の結果は呼び出し側のものです。
- 構築途中で失敗したら、そこまで作った部分を解放します。`H{a = open(), b = try^open()}` の2つ目が失敗すると `a` を解放します。
- `catch^` に移る前に、抜けるスコープの束縛を解放します。本体の名前は `catch^` から見えないので、順序は観察できる範囲で素直です。
- `panic^`・実行時エラー・エントリの `try^` の未捕捉エラーでは解放しません（巻き戻しをしません）。
- エントリファイルのトップレベルの束縛は、プログラムの終わりに逆順で解放します。

実行時のフラグ（Rust の drop flag）は要りません。値引数がなく、所有権が移るのは `return^` だけなので、解放するかどうかはコンパイル時に決まります。

### コピーしない

**`Disposable` を持つ型はコピーできません。** コピーすると同じ資源を二度解放するからです。合成の基底、フィールド、配列、合併へ波及します。

許すもの（名前を持たない一時値なので、ビットコピーしても他に残りません）:

```rhat
var^a = make()
a := make()
var^h = Holder{d = make()}
files.push(try^open(path))
files[0] := make()
return^make()
```

局所変数をそのまま返す `return^a` も許します。`a` はそこで解放せず、呼び出し側へ移ります。

拒否するもの:

- 変数・フィールド・要素・参照先からの束縛・代入・`push`・リテラルの要素、局所変数以外からの `return^`。
- 値引数と値の仮引数。`ref^` を使います。
- `repeat^`・`source...`・`append`。要素を複製します。
- `for^x in^xs`。`x` が要素のコピーになるので、添字で回します。

合併に入っている場合は、絞り込んだ名前がその場所を指します。`if^u fits^Device { u.write(...) }` は合併の中の値を操作します。
スライスの要素もその場所を読み取り専用で見せます。

### 一時値は受け取る

解放する一時値は格納するか束縛します。`make()` の結果を捨てる文、`make().x`、`make().m()`、`make() fits^ T` は拒否します。
文末に解放する規則より単純で、解放の時期が書いた通りになります。捨てるなら `let^_^ = make()` と書きます。

### dispose の形

- `abstract^dispose:p^self^;` を実装します。引数も戻り値もなく、**失敗しません**。自動で呼ばれる位置には誤りを返す先がないからです。
  失敗しうる後始末は `close()` のような普通のメソッドにして明示的に呼びます。その後の `dispose` は何もしないように書きます。
- `dispose` を明示的に呼ぶことはできません。二重解放になるからです。
- 解放は `p^` の処理なので、`f^` の中で解放が必要な値は扱えません。`f^` で作って返すだけなら許します。
- 名前が `dispose` のメソッドを持つだけでは対象になりません。`Disposable` の合成が必要です。

## コンテナ

**配列が所有し、ほかからは `ref^` で持ちます。**
`HashMap<K, Device>` は作れません。`set` の値引数と `get` の返り値がコピーになるからです。`get` のたびにコピーを返す動作はこの種の型に合いません。

```rhat
var^devices = Device[grow^]{}
var^names:c.HashMap<string^, ref^Device> = {}

devices.push(try^open(path))
names.set("main", ref^devices[devices.len - 1])
```

- 配列より長生きする map は `reference would outlive its owner` で拒否されます。
- `grow^` の領域は動かないので、`push` をまたいでも参照は有効です。
- `pop`・`clear`・`truncate` は、要素を指す参照が残っている間は拒否します（`flex^` の縮小と同じ検査）。解放済みの値を参照から触れないようにするためです。
- 配列と map は一つの型にまとめられません。どちらも所有領域を持つので、`intern` の `keys` と `pool` と同じく別の変数にします。
- 閉じた要素を再利用するなら `files[i] := try^open(path)` です。古い値は解放されます。空き番号の管理は利用者の仕事です。

## 制約

- 同じスコープで先に宣言した `Disposable` の値が、後の値を `ref^` で持つと、その `dispose` は解放済みの値を読みます。領域は残っているのでメモリ安全ですが、Rust の drop check ほど厳密には検査しません。
- `first^` の束縛には持てません。複数代入 `a, b := x, y` でも扱えません。
- `a = make()` のように演算子へ渡した一時値は解放されません。

## 検討経緯

一度 `with^` と `noncopy^` を実装しましたが、`with^` は L^ の GC を前提とした構文で R^ には不要でした。
`noncopy^` の検査は、ここで述べた「`Disposable` はコピーしない」の実装としてそのまま残しています。
コピーできるかどうかと解放するかどうかは Rust と同じく一体なので、独立したキーワードにはしていません。

ムーブ一般は Goose の可変長配列の `move` が入った時点で、その実装を参考に改めて検討します。
