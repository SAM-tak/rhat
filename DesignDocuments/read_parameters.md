# read^ 参照と経路ごとの変更権限

`ref^read^T` は、その参照経由の変更を禁止する読み取り専用参照です。
別の変更可能な参照・スライス・捕捉変数から同じ領域を変更することは許します。
参照先の値が一定であることや、別名参照がないことは保証しません。
ライフタイム注釈は要求せず、参照先の寿命・型・保存領域の有効性は独立して検査します。

## 型と変更権限

`p^` の参照引数は既定で借用先を変更できます。読むために渡す引数は `read^` にします。
`p^` の引数・戻り値・変数・フィールドに `ref^read^T` を使います。
通常の `f^` の引数には `read^` を明記せず、呼び出し元の変更権限を引き継ぎます。
参照の配列には `T[ref^read^N]`、動的参照には `ref^read^dyn^D` と書けます。
読み取り専用スライスは `read^T[..]` です。

```rhat
let^update = p^input:ref^read^Data, output:ref^Data {
    output.n := input.n + 1
}
var^data = Data{n = 1}
update(ref^data, ref^data)  # 同じ領域でも渡せる
```

- 変更可能から読み取り専用への変換は許し、逆方向は拒否します。
- コピー・格納・再借用・引数渡し・返却でも、読み取り経路の変更制限を保持します。
- フィールドや要素を経由して書くこと、変更するメソッドを呼ぶこと、変更可能な引数へ渡すことは拒否します。
- 読み取り経路から、変更可能な参照を含む値をそのままコピーすることも拒否します。
  直接の参照フィールドなら、`ref^read^T` の期待型を明示して読み取り専用で受け取れます。
- 読み取り専用の動的参照から、変更可能な参照を返すメソッドを呼ぶことは拒否します。
- スカラーや変更可能な参照を含まない値をコピーした後、そのコピーを変更することはできます。
- `ref^` 式は期待型が読み取り専用なら、`let^` の保存領域も借用できます。
  `let^r = ref^mutable_value` は、束縛だけを固定し、参照先を読み取り専用にはしません。

通常の `f^` は借用先を変更できず、`p^` も呼べません。
既存の `f^mutable^self^` と演算子の効果制限は維持します。
`p^` の引数を、実装が読むだけという理由で自動的に読み取り専用へ変えることはしません。

## f^ の引数と返り値の変更権限

通常の `f^` の参照・スライス引数は、変更可能・読み取り専用のどちらも受け取ります。
引数の `ref^T` / `T[..]` は書き込み権限を要求しません。明示的な `read^` は冗長指定としてエラーです。
`f^self^` にも同じ規則を適用します。`f^mutable^self^` の self は例外で、変更可能な参照を要求します。
引数のレコードや配列の要素型に含まれる読み取り参照は通常の型の一部なので、この禁止の対象ではありません。

```rhat
let^identity = f^x:ref^Cell -> ref^Cell { x }
var^a = Cell{}
let^r:ref^read^Cell = ref^a
let^read_result = identity(r)      # ref^read^Cell
let^write_result = identity(ref^a) # ref^Cell
```

各呼び出しの引数型で本体を特殊化し、返却式の参照・スライスの変更権限を推論します。
関係のない読み取り引数は返り値を読み取り専用にしません。
分岐から変更可能な参照と読み取り専用参照の両方が返る場合は、読み取り専用にまとめます。
複数の戻り値は各結果を別々に扱い、nil を含む合併型でも権限を保持します。
寿命の由来は従来の参照フロー解析で別途検査します。権限の推論によって参照の寿命は延びません。
固定サイズの値をコピーして返す場合、その値自身を読み取り専用にはしません。

本体がない外部関数などで由来を決定できない参照返り値は、注釈を要求します。
`read^(引数名)` は「常に読み取り専用」ではなく、「指定した引数の読み取り属性を引き継ぐ」です。

```rhat
let^identity = f^a:ref^Cell -> ref^read^(a)Cell { a }
let^choose = f^a:ref^Cell, b:ref^Cell, flag:bool^ -> ref^read^(a, b)Cell {
    if^flag { return^a }
    return^b
}
def^Box {
    self^{ n:i32^=0 }
    at = f^self^ -> ref^read^(self^)i32^ { ref^self^.n }
}
let^tail = f^xs:i32^[..] -> read^(xs)i32^[..] { xs[1..] }
```

複数の由来を指定した場合、いずれかが読み取り専用なら結果も読み取り専用です。
通常の返り値の `read^` は、引数の権限に関係なく常に読み取り専用を返します。
条件付き注釈は返り値専用で、存在する参照・スライス引数を名前で指定します。
本体がある関数は参照の由来と、各参照引数を独立に読み取り専用にした特殊化で契約を検査します。
本体のない外部宣言はプログラマーが保証する契約です。
動的呼び出しでは宣言の注釈を使い、オーバーライドは引数位置に対応した同じ契約を持つ必要があります。

## 別経路からの変更

```rhat
var^a = Cell{x = 1}
let^r:ref^read^Cell = ref^a
a.x := 2
print^(r.x)  # 2
r.x := 3     # エラー: read^ 経由では書けない
```

読み取り保護期間は設けません。後続引数の評価中、関数の別引数、捕捉変数、静的状態からの変更も許します。
最適化で `read^` だけを根拠に値の不変性や別名不存在を仮定しません。

既存部分のスライスを読みながら、同じ `grow^` 配列へ追記できます。
伸長しても既存要素のアドレスは動かず、スライスの長さは取得時のままです。
非所有・非 Disposable 要素の `grow^` は、論理長を縮めても保存領域を保持します。
残ったスライスは同じスロットを指し続け、再追記でその内容が変わることがあります。

## 寿命と参照の流れ

参照は実際の所有者より長く生きられません。これは変更可能な参照と同じ規則です。
読み取り専用に変換したブロックの外への保存・返却も、参照先が十分長命なら許します。

```rhat
let^view = f^x:ref^T -> ref^read^T {
    let^r:ref^read^T = x
    return^r  # x の参照先に由来するので返せる
}
```

関数内のローカル値そのものを指す参照は返せません。
参照を含む構造体・配列・合併の保存や返却も、通常の由来の追跡と関数間の参照フロー要約で検査します。
読み取り参照のためだけの保護境界はありません。
参照フィールドが別経路から差し替えられる場合も、保存先の寿命検査と由来の合併を行います。

## 型と保存領域の有効性

別経路からの変更を許すことは、無効になった参照の使用を許すことではありません。

- `flex^` の縮小、所有行や Disposable 要素の除去は、内部を指しうる参照が残っている間は拒否します。
  読み取り参照・スライス・動的参照・構造体等に格納した参照と、評価途中の前の引数も対象です。
- ユニオンや nil の型の絞り込みは、別名からの変更で無効化します。
  異なる外部由来の引数は同じ領域を指す可能性があるため、関係するパスの判定を保守的に破棄します。
- コピー可能なユニオンの選択肢は独立した値として取り出します。
  所有・Disposable の選択肢はその場所を使い、読み取り経路の権限を引き継ぎます。
- Disposable を含むユニオンの置き換えでは、選択肢内部を指しうる参照が残っていないか検査します。
  構造体や固定配列に入れたユニオンも対象です。配列全体やユニオン全体への参照と、内部への参照は区別します。
- 縮小・要素破棄・変種差し替えの可能性は呼び出し側へ伝えます。
  動的呼び出しで必要な要約を使えない型には、既存の flex^ と同様の制限を置きます。
- 所有行の構築中に同じ配列を変更することは、引き続き拒否します。

検査はスコープ単位で、由来と型を保守的に扱います。安全な別要素・別フィールドの変更も拒否する場合があります。
関数間の参照フローと無効化の要約には既存の上限がありますが、読み取り保護専用の64引数制限は廃止しました。

## let^・外部関数・スレッド

`let^` 自身の保存領域は引き続き変更できません。`let^` から `f^` が返す参照やスライスも、
由来の印によって元の領域への書き込みを拒否します。
`let^h = Holder{target = ref^t}` の `h.target` のように、別の値への変更可能な参照を格納している場合は、
その参照先 `t` を変更できます。`let^` と `read^` は異なる指定です。

`externC^` の `read^` は、その引数経由で書かないという外部宣言の契約です。
外部コード自体の正しさは R^ の静的検査だけでは保証しません。
通常の参照はスレッドをまたいで共有せず、独立したコピーと Channel の所有管理を使います。
`read^` はスレッド安全性や同期の指定ではありません。

設計の変更経緯と監査項目は [移行計画](read_path_migration.md) を参照してください。
