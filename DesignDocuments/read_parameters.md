# `read^` 参照とレキシカルな読み取り借用

`ref^read^T` は読み取り専用参照です。読み取り借用はレキシカルスコープ単位で保護し、
保護スコープ外への持ち出しをコンパイル時に拒否します。ライフタイム注釈は要求しません。

## 目的と基本方針

`p^` の参照引数は、現状どおり既定で借用先を変更できるものとします。
必要な引数だけを読み取り専用にする指定として、`immutable^` や `const^` よりも
「読むために渡す」という用途が分かりやすい `read^` を使います。
引数、戻り値、変数、フィールドに共通して `ref^read^T` を使います。
参照の配列には `T[ref^read^N]`、動的参照には `ref^read^dyn^D` と書けます。

```rhat
let^inspect = p^input:ref^read^Data, output:ref^Buffer {
    # input を読み、output を変更する。
}
```

通常の `f^` は既に借用先を変更できず、`p^` も呼べません。
演算子の自動借用にもこの既存の効果制限を使い、`read^` の導入を前提にしません。
既存の `f^mutable^self^` は維持します。

## let^ から返された参照

`let^` の値から `f^` が返した参照やスライスでは、`let^` の中身を変更できません。

```rhat
let^a = T{}
let^r = a.me()      # me = f^self^ -> ref^T { self^ }
r.add()             # エラー: cannot modify let^ binding 'a'
print^(r.n)         # 読むのは自由
```

型は `ref^T` のままで、`read^` にはしません。`let^` の束縛の由来（`Roots`）に印を付け、書き込みの時点で由来を見ます。
`read^` と違って読み取り借用を始めないので、別の保護は生じません。`let^` はもともと変更できないからです。

- `var^` の値から返された参照は、今まで通り書き込めます。
- `let^` の値の中にある別の値への参照（`let^h = Holder{target = ref^t}` の `h.target`）は、`t` を指すので書き込めます。`let^` が固定するのは自身の保存領域だけです。
- `p^` の書き込み可の引数に渡すのも拒否します（`bump(a.me())`）。呼び出し先で書き込まれるからです。

## 求める保証

以下の二つは異なる保証です。

1. 指定した引数を経由する変更だけを禁止する。別のエイリアスによる変更は許す。
2. 指定した領域が読み取り借用の保護期間中に変化しないことを保証し、別のエイリアスによる変更も禁止する。

後者を採用します。
例えば上記の手続きに同じ領域を `input` と変更可能な `output` の両方として渡す場合は、
読み取り専用の保証を破る可能性があるため拒否します。
他の引数、既存の参照、内部参照、手続き間で転送された参照や、
暗黙に渡されるトップレベル変数の参照も検査の対象です。

オブジェクトを永久に不変にする仕組みではありません。参照の変更権限と、
借用による領域の保護を分けて追跡します。変更可能な参照から読み取り専用参照への変換は許し、
逆方向の変換は拒否します。参照のコピー・格納・引数渡し・返却でも変更制限を保持します。
`ref^` 式は期待型が読み取り専用参照なら `let^` の保存領域も借用できます。
`let^r = ref^mutable_value` という束縛自体は、読み取り専用参照の指定にはなりません。

## 保護期間と持ち出し禁止

読み取り借用には保護スコープを持たせます。呼び出し元で読み取り参照を取得する場合は、
取得する式を含む最内のレキシカルブロックを保護スコープとします。
最終使用では解除せず、ブロックを抜けるまで対象への変更を禁止します。
式の結果を捨てる場合も同じです。保護期間を短くしたい場合は明示的な `do^{ ... }` を使います。

```rhat
# 概念例。view は a に由来する読み取り専用参照を返す。
do^{
    let^r = view(ref^ a)
    a.change()            # エラー：読み取り借用中
    use(r)
    a.change()            # エラー：最終使用後も保護を継続
}
a.change()                # 保護が終わったので許可
```

読み取り専用引数のためだけに始める借用は、引数がその読み取り借用に変換される時点から
呼び出し終了まで保護します。後続引数の評価中の変更も検査します。
戻り値としてその借用を受け取る場合は、呼び出し終了では解除せず、上記の呼び出し元の
ブロック末尾まで保護します。既に保護中の参照を渡す場合は、元の保護スコープを引き継ぎます。

参照を保護スコープの外へ保存・返却する操作はコンパイルエラーにします。
参照を含む構造体・配列・スライスなどを経由する持ち出しも同じです。
保護スコープを外側へ延長して持ち出しを許す機能は、初版では導入しません。

```rhat
# T と view が定義されている場合の例
var^outer:ref^read^T | nil^ = nil^
do^{
    let^r = view(ref^ a)
    outer := r           # エラー：保護スコープ外への保存
}
```

ただし、関数呼び出しの境界を越えること自体は禁止しません。保護スコープ内で呼んだ関数へ
渡し、その関数が引数由来の読み取り参照を返すことは許します。例えば `view(ref^ a)` の
返り値は呼び出し元で保護され、view の終了時に保護が切れることはありません。
その呼び出し元の保護スコープより外へ返す操作は拒否します。
引数由来の参照を返却式で直接読み取り専用に変換する場合も、呼び出し元に保護を引き継ぎます。
一方、関数内のローカル変数で新たな読み取り借用を開始してから、それを関数外へ返すことはできません。

```rhat
let^view = f^x:ref^T -> ref^read^T { x }  # 呼び出し元で保護
let^forward = f^x:ref^read^T -> ref^read^T { x }  # 既存の保護を引き継ぐ
# 次は呼び出し時に拒否する。
let^bad = f^x:ref^T -> ref^read^T {
    let^r:ref^read^T = x  # この関数のブロックが保護スコープ
    return^r              # エラー：保護スコープ外への返却
}
```

ユーザーによるライフタイム注釈は要求せず、引数・戻り値の由来と保護スコープを内部で追跡します。
由来が複数ありうる場合は候補をすべて保護し、外へ出ないことを証明できない保存・返却は拒否します。

## 実装と保守的な制限

既存の借用元追跡 `Roots` と寿命検査に、読み取り借用の境界を追加しています。
参照の実行時表現は通常の `ref^T` と同じで、保護と権限はコンパイル時に検査します。
関数内部で作った借用と別の引数からの変更についても、引数間の競合を記録し、
呼び出し元で実際の由来が重なるか検査します。この情報はラッパー・再帰・動的呼び出しを通じて伝播します。

- 保護スコープと、重なる領域への変更経路を追跡する。最終使用による解除は行わない。
- フィールド、配列要素、スライス、内部参照にも参照の由来と保護境界を伝播する。
- 参照のコピーや別の手続きへの転送で、制限が失われないようにする。
- 通常の呼び出し、再帰、オーバーロード、`dyn^` の呼び出しにも規則を適用する。
- 外部関数が参照先を変更する可能性を、外部宣言の契約として扱う。
  外部コード自体の正しさを R^ の静的検査だけで保証するものではない。
- 戻り値に参照・スライスが含まれる場合も、呼び出し元に借用の由来と保護を伝播する。
  外側への保存、集合値を介する保存、別の関数経由の保存でも持ち出し禁止を検査する。

初版は借用元のオブジェクト全体を保守的に保護し、変更可能な引数との重なりを拒否します。
`p^` の変更可能な参照引数は、実際に書き込まない実装でも変更しうるものとして検査します。
戻り値に参照を含む呼び出しは全引数の由来を引き継ぐため、無関係な引数まで保護する場合があります。
読み取り専用の `dyn^` レシーバーから、変更可能な参照を返すメソッドの呼び出しは拒否します。
読み取り専用経路から、変更可能な参照を含む値をそのままコピーする操作も拒否します。
直接の参照フィールドなら、`ref^read^T` の期待型を明示して読み取り専用参照として受け取れます。
関数間の競合情報は64引数までを扱います。64引数を超える関数での読み取り借用や、
その上限を超える呼び出しで競合の追跡が必要になる場合は、検査を省略せず診断します。
同じオブジェクトの別フィールドを独立に扱う精度向上や、実際には変更しない引数を許す効果解析は、
追加の検討事項とします。不必要な拒否の削減は、保証を弱めずに進める必要があります。

`op^[]` の構文や、レシーバーの変更権限による添字演算子の選択は、この機能とは別です。
