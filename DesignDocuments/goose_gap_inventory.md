# Goose と R^ の機能差分棚卸し

調査日: 2026-11-09。R^ は `5b10996`、Goose は手元のチェックアウト
`2ed1a63dde2ddff777fbb7f4790412b4f00cd47d`（2026-10-30）を対象とします。
Goose の最新公開版すべてを追跡した一覧ではありません。
配列表記は、その後合意した括弧付きの型表記へ更新しています。
主対象はメモリモデルと、それに直接関わる言語機能です。周辺の言語・ライブラリ差分も末尾に記します。
実装調査を記録する文書であり、ここで新たな採用・不採用は決定しません。

## 状態の読み方

- **不採用・別方式**: 既存の R^ 設計文書に明記された方針。
- **未実装**: R^ に対応機構がないもの。実装がないだけでは、不採用とはしない。
- **一部対応**: 目的の一部は実現できるが、同等の言語機能ではないもの。
- **双方で未実装**: Goose の研究ノート・将来計画であり、Goose の実装済み機能との差に数えないもの。

## `(T[])[grow^]` は先送りだったか

既存の [arrays.md](arrays.md#可変サイズ配置を採用しない理由) では、`[varint]` だけでなく、
**可変サイズの要素を一続きのメモリに詰める Goose の配置そのものを採用しない**と決めています。
Goose の `T[][>..]` はその配置を使う機能です。内側は構築後に長さが固定され、
外側だけに完成した要素を追加できます。要素のバイト数が違うため、配列は順次走査用で、通常の添字アクセスはできません。

現在の R^ でコンパイラに確認した結果は次のとおりです。

| R^ の型 | 結果 | 意味 |
| --- | --- | --- |
| `(i32^[])[grow^]` | 拒否 | 所有配列を所有配列の要素にはできない |
| `(i32^[2])[grow^]` | 許可 | 固定長2要素の行を並べる伸長配列 |
| `(i32^[..])[grow^]` | 許可 | 別の置き場を借用するスライスを並べる伸長配列 |
| `i32^[max^8 [grow^]]` | 許可 | 外側が最大8行の独立した伸長領域を所有するジャグ配列 |
| `i32^[8 [grow^]]` | 許可 | 固定8行の独立した伸長領域を所有するジャグ配列 |

最初の診断は `owning array elements must be nonempty fixed-size values` です。
スライスを要素にする例は、型注釈を使って `var^rows:(i32^[..])[grow^] = {}` と書けます。
行の本体の寿命は、保存したビューより長くする必要があります。

ただし、**Goose のインライン配置を採らないことと、独立した領域を所有する可変長の行を将来も絶対に許さないことは別**です。
後者は現在、外側が固定長 `N` または静的上限 `max^N` の場合に記述子と別領域で実装しています。
固定長・上限からスタック数を静的に予約し、外側が行の構築・削除・寿命を管理します。
外側の行数・上限が実行時に決まる形は、必要な独立データスタック数をコンパイル時に決められないため拒否します。[arrays.md](arrays.md#行を所有するジャグ配列) を参照してください。

一方、別々の変数が所有する伸長配列への参照を並べることは、既にできます。
`var^rows:(i32^[grow^])[ref^] = {ref^a0, ref^a1}` から `rows[0].push(10)` を呼べます。
外側を `[ref^grow^]` にして参照の一覧自体を伸ばす形も、構文検査とネイティブ実行で確認しました。
この場合の所有者は `rows` ではなく `a0`・`a1` です。行を実行時に新規所有として追加し、
外側の破棄と一緒に各行も破棄する機能とは区別します。

## メモリ関連の差分

Goose 側の基準は [仕様](https://github.com/aardappel/goose/blob/2ed1a63dde2ddff777fbb7f4790412b4f00cd47d/docs/goose_spec.md) です。
節番号はこの版を指します。

| 機能 | Goose | 現在の R^ と既存の判断 |
| --- | --- | --- |
| 可変幅整数フィールド・長さ欄 `[varint]` | 実装済み。§3.6 | **言語機能として不採用**。通信上の可変長整数は I/O ライブラリで扱う余地がある。[arrays.md](arrays.md#構築時に容量を決める所有配列-tmax) |
| 可変サイズ要素のインライン配列 `T[][>..]` | 実装済み。§3.3。要素ごとに大きさが違い、順次走査する | **Goose の配置は不採用**。独立した行を所有する方式は、外側が固定長 `N` または静的上限 `max^N` の場合に実装済み |
| 可変サイズフィールドの後ろにもフィールドを置く | 実装済み。§3.4。後続位置を動的に計算する | **Goose の可変サイズ配置は不採用**。R^ の所有フィールドは末尾に一つまで |
| 可変モードの ADT `Shape..` | 実装済み。§3.5。タグ＋実際の候補の大きさで格納する | **対応機構なし**。R^ の合併はタグ＋最大ペイロード。可変サイズ配置の不採用方針に関係する。今後の検討をすべて禁止した個別決定とは区別する |
| 既定でパックする構造体・明示 `pad` | 実装済み。§3.2、Appendix C | **未実装**。R^ は自然アラインメントとパディング。可変サイズ配置とは別の論点で、不採用決定は確認できない。[design.md](design.md) |
| 長さ欄の幅指定 `T[u8]` など・上限付き配列の最小幅の長さ欄 | 実装済み。§3.3 | **未実装**。R^ の配列長は基本的に64bit。`[varint]` を不採用にしたことだけでは、固定幅メタデータの短縮まで除外されない |
| 候補数に応じた ADT タグ幅 | 実装済み。Appendix C。現 C backend は通常 u8、候補数により u16 | **未実装**。R^ は32bit固定。直前の議論で検討したが、変更はまだない |
| `root struct` | 実装済み。§3.4。複数の独立した所有領域を一つの所有寿命へまとめる | **未実装**。R^ では所有フィールドを末尾に一つしか置けず、同等の所有者型はない。Goose でも root 自体はパックされた値ではないので、可変サイズ配置の不採用とは独立に検討できる |
| 自己相対参照・プール相対参照 `T&<u32>`、`T&<u32 in pool>` | 実装済み。§3.9。狭いオフセットとして保存する | **未実装・別途設計**。通常の `ref^` はポインター。基準所有者を型引数で指定する仕組みも未設計。[generics.md](generics.md#現在の範囲) |
| 範囲保証付き添字・境界型 `u32 in nodes`、`u32 upto edges` | 実装済み。§3.11。検証済みの範囲を型として保持する | **未実装**。R^ の通常の整数添字とループ範囲解析は別物 |
| `checkfree fn` | 実装済み。§7.14。境界検査が残るとコンパイルエラーにする | **未実装**。R^ にも境界検査削減の最適化はあるが、検査ゼロを要求する言語契約はない |
| `slot_pool<T>` / `slice_pool<T>` | 標準ライブラリとして実装済み。空きスロット・可変長の連続区間を再利用する | **専用ライブラリなし**。R^ の `HashMap`、伸長配列、ビューで構成する余地はあるが、同等の標準 API としては提供していない |
| 保存イメージの `to_bytes` / 検証付き `from_bytes` | 実装済み。§12。配置・タグ・長さ・相対参照などを検証して復元する | **そのままの配置を保存する方向は採らない**。R^ は型ごとのストリーム読み書きを基本方針とする。汎用の型別シリアライザーが実装済みという意味ではない。[arrays.md](arrays.md#可変サイズ配置を採用しない理由)、[io.md](io.md) |
| 明示的な `trim_memory()` | `os` ライブラリに実装済み。未使用のデータスタックページを OS へ返す | **公開 API なし**。R^ の `flex^` は大きく縮めた際に自動 decommit するが、全スタックへ明示的に要求する操作とは異なる |
| 所有配列全体の再代入 | Goose の配置・参照・スタック制約を満たす範囲で対応。§4.4、§5.3 | **未対応の範囲がある**。R^ の所有配列は一般のコピー・再代入を禁止し、返却先への直接構築を使う。所有値の一般的な移送とは分ける |

相対参照と、範囲保証付きの整数添字は別機能です。両方とも小さい整数を保存しますが、
前者は参照を復元し、後者は配列との関係を型で保持します。
`root struct` も「所有配列を任意個ネストできる」機構ではありません。所有者の置ける場所に制限があります。

## 既に同種の機能がある項目

次は「Goose にしかない機能」へ数えません。配置・検査の細部は異なります。

| Goose | R^ |
| --- | --- |
| 固定長配列 `T[N]` | `T[N]` |
| 構築後に長さ固定の `T[]` | `T[]`。要素は非所有・固定サイズに制限し、インライン配置ではなく記述子を使う |
| 伸長 `T[>..]` | `T[grow^]` |
| 伸縮 `T[>..<]` | `T[flex^]` |
| 静的容量 `T[..N]` | `T[max^N]` |
| 構築時に容量を決める `T[..]` | `T[max^]` |
| 借用スライス `T[:]` | `T[..]` |
| 寿命推論・安定アドレス・返却先への直接構築 | 実装済み。R^ は参照の流れの要約など独自の解析を使う |
| 静的関数値・外側のローカル捕捉 | R^ も呼び出し元の寿命内での捕捉とコールバック受け渡しを実装済み |
| スレッドごとのメモリ分離とメッセージ通信 | R^ は `std.thread` とインスタンスごとの `Channel<T>` |

Goose の grow-only の縮小と R^ の `grow^` の縮小も、同じ動作とは限りません。
R^ は論理長を縮めても最大末尾を保持し、保存領域を戻す用途は `flex^` へ分けています。
また R^ は、構造体・配列に入った参照についても `flex^` の縮小を検査します。
Goose の制限をそのまま採用していない部分です。[arrays.md](arrays.md#grow-と-flex-の縮小)

## メモリ以外で残る主な差分

| 項目 | R^ の現状 |
| --- | --- |
| `const for` によるフィールド・変種・型列の構造的リフレクション | **一部対応**。`inline^for^` は異種引数列・固定長配列を展開するが、フィールドアクセサーや変種列の反射はない。[inline_for.md](inline_for.md) |
| `simd fn` による CPU 命令セット別の関数生成と実行時選択 | **未実装**。LLVM の自動ベクトル化や数学ベクトル型の存在とは別 |
| `defer` による任意のスコープ終了処理 | **構文なし**。`Disposable` はあるが、任意の後始末文を登録するものではない |
| `return ... from` による複数の呼び出しを越える返却 | **同等機構なし**。R^ のエラー合併・`try^`・`catch^` は別方式 |
| ワーカー生成時のグローバルのスナップショット | **明示的に不採用**。R^ は起動引数へ必要な値を入れる。[threads.md](threads.md#スレッドの入口とトップレベル束縛) |
| ワーカー内の失敗をそのワーカーへ封じ込める contained worker | **未実装**。R^ の未処理ワーカーエラーはプロセスを診断終了する |
| タイムアウト付き queue 受信、複数箇所からの worker wait | **同等 API なし**。R^ の Channel は時間制限未対応、Thread は所有ハンドルによる join。採用可否は別途検討 |
| ファイルのコンパイル時埋め込み `embed_file` | **対応する公開構文なし** |
| 主要な標準ライブラリ差分 | Goose の `binary`、`base64`、`csv`、`json`、`regex` などに相当する標準モジュールは R^ にない。機能別の詳細調査は別途必要 |

グラフィックス・音声・UI・物理や、別プロジェクトの `rhat-gfx` は今回の対象から外します。
標準ライブラリの全関数、エディター、パッケージ配布・バックエンド・ターゲット対応を網羅した一覧ではありません。

## Goose 側も未実装のもの

| 項目 | Goose 側の状態 |
| --- | --- |
| 伸長可能な要素を配列へ入れ、完成済みの内側も任意に伸ばすこと | `nested_growth.md` の研究段階。完成して長さが固定された可変サイズ要素の配列とは異なる |
| SoA / column arrays `T[\|\|..]` | `soa.md` に明記された未実装の提案 |
| コルーチン・非同期タスク | `coroutines.md` の研究段階 |
| 所有する伸長配列の一般的な move | 仕様 Appendix B の未解決項目。R^ 側も検討を保留している。[dispose.md](dispose.md#検討経緯) |
| root 所有者のネスト・root 所有者の配列 | Goose の将来項目。現在の `root struct` と混同しない |

Goose の設計文書があることを、その機能が使える証拠にはしません。

[`soa.md`](https://github.com/aardappel/goose/blob/2ed1a63dde2ddff777fbb7f4790412b4f00cd47d/docs/design/soa.md)、

## 次に検討するなら

ここは新規の評価であり、採用決定ではありません。

1. **root 型に相当する所有者**。複数の独立した伸長領域をまとめたい要求に直接効き、インライン可変サイズ配置とは切り離せる。
2. **相対参照、範囲保証付き添字**。密度改善と境界検査の削減を別々に評価する。先に具体的な用途を選ぶ。
3. **小さいタグ・長さ欄、必要なら固定サイズ型のパック**。測定可能な配置最適化として検討できる。
4. **slot / slice pool ライブラリ**。言語を拡張せず実現できる範囲を調べる。

Goose のインライン可変サイズ配置を再導入する判断は、上の機能とは独立に扱います。
