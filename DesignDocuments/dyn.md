# 動的ディスパッチ（ref^ dyn^）

```rhat
def^ Shape {
  abstract^ area:f^ self^ -> f64^;
  describe = p^ self^ { print^("area", self^.area()) }
}
def^ Square : Shape { self^{ side:f64^ = 2.0 } area = f^ self^ -> f64^ { self^.side * self^.side } }
def^ Circle : Shape { self^{ r:f64^ = 1.0 } area = f^ self^ -> f64^ { 3.0 * self^.r * self^.r } }

var^ a = Square{}
var^ b = Circle{}
var^ all:(ref^ dyn^ Shape)[2] = [ref^ a, ref^ b]    # 型の異なる値を混ぜる
for^ var^ i:i64^ = 0 while^ i < 2 next^ i += 1 { all[i].describe() }
```

## 静的ディスパッチとの関係

R^ のメソッドと関数は、受け手・引数の具体的な型ごとに特殊化します（[設計の「定義と合成」](design.md)）。
`ref^ Shape` を受ける関数に `ref^ Square` を渡すと `Square` 用の関数が生成され、
`override^` した実装も静的に選ばれます。値の具体型は常にコンパイル時に分かっているため、
仮想関数表も `virtual` 相当の印も要りません。

`ref^ dyn^ Shape` は、具体型をコンパイル時に知らないまま扱うための型です。Rust の `&dyn Trait` に相当します。
定義の側には何も書かず、使う側の型で静的か動的かを選びます。同じ `Shape` を、
普段は `ref^ Shape`（特殊化）で、型を混ぜたい箇所だけ `ref^ dyn^ Shape` で使えます。

## 表現と変換

`ref^ dyn^ D` は {データへのポインタ, メソッド表へのポインタ} の2語です。単独の `dyn^ D` は書けません。

期待型が `ref^ dyn^ D` の位置（引数、注釈付きの束縛、配列リテラルの要素など）では、
`ref^ T` を暗黙に変換します。`T` は `D` を合成した具体的な（抽象メンバの残っていない）型です。
変換が起きた (`T`, `D`) の組ごとに、`D` のメソッドを `T` 用に具体化した表を作ります。
表はプログラム全体で一つのアドレスを持ちます。(`T`, `D`) から決まる名前の `linkonce_odr` 定数として、
使う IR モジュールがそれぞれ同じ内容を出力し、リンク時に一つにまとまります。

寿命は通常の `ref^` と同じ規則です。データ側の参照元を引き継ぐため、局所の値を `ref^ dyn^` として返すことはできません。

## 呼べるメソッド

`dyn^` 経由で呼べるのは `D` のメソッドだけで、フィールドには触れません。表の各要素はすべての具体型で
同じ署名を共有するため、次の条件を満たすメソッドだけが表に載ります。

- 最初の引数が `self^` の通常のメソッドで、`template^`・演算子・オーバーロードではない。
- 残りの引数がすべて具体的な型で注釈されている（抽象定義・関数型は不可）。
- 結果が注釈されている。省略できるのは何も返さない `p^` だけ。所有値（`grow^` など）は返せない。

条件を満たさないメソッドがあっても変換はできます。`dyn^` 経由でそのメソッドを呼んだ時点で拒否します。
引数は宣言された型と完全に一致する必要があります（合成先の型への暗黙の受け渡しはしません）。
`f^` からは `p^` のメソッドを呼べません。

## 解析

`dyn^` 経由の呼び出しは、その `D` について作られたすべての表の該当要素を呼びうるものとして、
コールグラフに辺を足します。データスタックの必要数、再帰の検出（所有値を抱えた再帰呼び出しの拒否）、
配列の縮小可能性の推論は、この候補集合の上で通常の呼び出しと同じように行います。

## ダウンキャスト（`fits^`）

```rhat
let^ probe = p^ x:ref^ dyn^ Base {
  if^ x fits^ D2 { print^(x.b) }                 # 具体型がちょうど D2
  if^ x fits^ dyn^ D2 { print^(x.name()) }       # D2 を合成した型（D3 なども含む）
}
```

- `x fits^ T`: 具体型がちょうど `T` かを調べます。真の分岐で `x` は `ref^ T` になり、フィールドにも触れます。
  `T` を合成した型（`D3 : D2` の `D3` など）は偽です。真の分岐でも具体型が正確に分かっているので、
  「値の具体型は常にコンパイル時に分かっている」という前提が保たれます。
- `x fits^ dyn^ D`: 具体型が `D` を合成しているかを調べます。真の分岐で `x` は `ref^ dyn^ D` になり、
  `D` のメソッドは `D` の表を引いて呼ぶため、合成先の `override^` も正しく効きます。
- 抽象定義へのちょうどの一致はありえないので、`x fits^ Base` は拒否し、`fits^ dyn^ Base` を案内します。
- 偽の分岐で `x` の型は変わりません（「`D1` ではない」という型は表せません）。
- `for^ x { when^ fits^ D1: ... }` の形でも使えます。

判定は表のアドレスの比較です。完全一致は一回、`fits^ dyn^ D` は `D` を合成した具体型の表の数だけ比較します。
候補は全体解析で確定します。`fits^ dyn^ D` で必要になる `D` の表は、解析の最後に不動点で作ります。

合併型の `fits^` は公称的な合成関係で判定しますが、`dyn^` の値に対して `dyn^` なしの型を書いた場合だけは
完全一致の意味になります。
