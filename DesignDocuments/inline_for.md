# 型の異なる可変長引数と inline^ for^ in^

実装済みです。`print^` のような「型の異なる値を任意個受け取り、型ごとに処理する」関数を
利用者が書けます。

## 背景

`print^` は整数・浮動小数点・文字列・bool を任意個混ぜて受け取り、型ごとの表示をコンパイラが出し分けます。
R^ の可変長引数 `...:T` は同じ型の値しか受け取れないため、`print^` は R^ の関数として書けません。

Rust では `println!` をマクロで提供しますが、その中身もコンパイラ組み込みの `format_args!` です。
Rust でマクロが多用されるのは、可変長ジェネリクス・既定引数・リフレクションがないことの穴埋めでもあります。
Goose は汎用のマクロを持たず、具体化の時点で構造的な並び（フィールド・変種・型の列・定数の列）を
展開する `const for` で、derive マクロやリフレクションの用途を賄っています。

R^ でも、トークンを書き換える汎用マクロではなく、型検査された構造の上で展開する仕組みを採ります。
具体化・寿命・データスタック計画などの静的解析と噛み合い、ビルドの重さや衛生性の問題も起きません。

## 構文

```rhat
let^ show = template^ p^ ... {
    inline^ for^ x in^ ... { write(x) }   # 型ごとの write はオーバーロードで選ぶ
}
show(1, "two", 3.0, true^)
```

- `template^` 関数の型注釈のない `...` を、呼び出しごとに型が決まる値の並びとします。
  `template^` の型注釈のない引数が呼び出しごとに型を決めるのと同じ規則です。
- 型注釈付きの `...:T` は従来どおり同じ型の可変長引数（`T[..]`）です。
- 実行時の何でも入る型（L^ の `any^`）は導入しません。`...:any^` のような綴りは、
  L^ の `any^` と意味が異なり誤解を招くため採りません。

## 型の並び `...` の扱い

- スライスではなく、要素ごとに型の異なる値の並びです。使えるのは次だけです。
  - `inline^ for^ x in^ ... { }` による要素ごとの展開
  - `....len`（コンパイル時の定数）
  - 別の関数への転送 `g(...)`（相手は型の並びか、要素型が一致する `...:T`）
- `...[i]` は `i` がコンパイル時の定数のときだけ許します。実行時の添字は要素ごとに型が違うので不可です。
  整数リテラル、固定長配列・引数列の `.len`、それらを使った `+ - * / %` と単項 `-`、
  その値を束縛した整数の `let^` に対応します。ユーザー関数の実行や `var^` は対象外です。
  現在の定数評価は各計算結果が ±2^30 以内の式に限ります。範囲外の添字はコンパイル時エラーです。
- 具体化のキーは実引数の型の並びです。現在の具体化（`instance_for`）は型のリストをキーにしているので、そのまま延長できます。
- 型の並び自体の束縛・返却・参照取得・配列への格納はできません。個々の要素は通常の値として使えます。
  所有値は要素にできないので `ref^` で渡します。参照の読み取り属性と借用元は維持します。
- 固定長配列の `g(array...)` は型の並びへ転送できます。要素数が実行時に決まるスライス・可変長配列は転送できません。
  通常の `...:T` への転送では、従来どおり実行時の長さも扱えます。

## inline^ for^ in^

- 本体を要素ごとに複製し、各複製の中で `x` はその要素の型を持ちます。オーバーロードの選択も複製ごとに行います。
- 要素数がコンパイル時に分かる固定長配列 `T[N]` にも使えます。スライス・可変長配列には使えません。
- 対象式は一度だけ評価し、値を保存してから走査します。元の配列を本体で変更しても走査する値は変わりません。
  `x` は各反復のスコープにある `let^` 相当の値です。参照要素なら通常の参照の規則で参照先を操作できます。
- `break^` は展開後の残りを飛ばし、`next^` は次の要素へ進みます。条件付きのジャンプも使えます。
  通常のループと同じく `break^^` / `next^^` や `[深さ]` で外側のループを指定できます。
- 各反復は独立したレキシカルスコープです。局所値への参照や、その反復で開始した `read^` 借用を
  外側へ持ち出すことはできません。反復を抜ければ、そのスコープの読み取り保護も終了します。
- `return^` の結果型は通常の分岐と同じ規則で合流します。無条件に `return^` する反復の後は展開しません。
  例えば `inline^for^x in^... { return^x }` は先頭要素の型を返します。
  複数の反復から互換性のない型を返す場合は、通常の結果型推論と同じくエラーです。
- 空の引数列は本体を展開せず、型検査もしません。
- 一つの具体化された関数で、入れ子を合計して 4096 反復まで展開します。引数列も 4096 要素までです。

## 対象外

- 型の並びを構造体のフィールドとして保持すること（タプル型）は対象外とします。
- `print^` は言語組み込みのまま残します。型の並びを表示するときは `inline^for^` で個々の要素を渡します。
