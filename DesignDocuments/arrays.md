# 配列の種類・リテラル・スライス

配列の種類・容量・要素の参照修飾は型の後ろの `[]` にまとめます。
旧型構文の前置 `grow^ T[]`・`flex^ T[]`・`T[:]`、Goose の上限付き配列 `T[..N]`、旧スライス型 `T[slice^]` は受け付けません。
値は構造体と同じく波括弧で書き、`T[...]{a, b}` または期待型に従う `{a, b}` です。
式のスライス取得には引き続き範囲表記 `values[start .. end]` を使います。

## 配列の種類

種類はハット識別子で指定します。

- `T[N]`：固定長配列。型のない `{a, b, c}` は `T[3]` です。N は[整数の定数式](#配列長の定数式)でも書けます。
- `T[N, M, ...]`：固定長の多次元配列。型と添字はどちらも外側の次元から書きます（[固定長の多次元配列](#固定長の多次元配列)）。
- `T[]`：構築時に長さを決め、その後は長さを変更しない所有配列。要素の書き換えは可能です。
- `T[grow^]`：伸長のみの配列。旧記法 `T[>..]` を置き換えます。
- `T[flex^]`：伸長・縮小の両方ができる配列。Goose の `T[>..<]` に相当します。
- `T[max^N]`：上限付き配列。最大 N 個の要素の保存場所を値の中に持ちます。所有する行を要素にした場合は、その行の領域も管理します。
- `T[max^]`：容量を構築時に決める所有配列。その容量内で伸縮します。Goose の `T[..]` に相当し、`T[max^](capacity)` で作ります。
- `T[..]`：借用スライス。他の配列の要素の並びを指すビューで、所有も伸縮もしません。Goose の `T[:]` に相当します。
  式の `a[..]`（全体）や `a[i .. j]` が作る値の型であり、どの種類の配列からも取得できます。
  要素は書き換えられます。読むだけなら `read^T[..]` です（[スライスの書き込みと read^](#スライスの書き込みと-read)）。
  配列の種類ごとの操作（`push` など）が要るなら、配列全体への参照 `ref^ T[grow^]` を使います。

```rhat
var^nodes = Node[grow^]{Node{}, Node{}, Node{}}
var^queue:Job[flex^] = {}
let^make = p^ pool:ref^Node[grow^] -> i32^ { ... }
```

外側の `ref^` は後続する型全体への参照です。`ref^Node[grow^]` は伸長配列全体への参照、
`Node[ref^grow^]` は参照の伸長配列です。`[]` 内では要素の `ref^`、次に種類・容量の順に書きます。
`Node[ref^max^10]` は `(ref^Node)[max^10]` と同じ型です。
参照の重ね掛けは `Node[ref^^max^10]`、配列の入れ子は `(Node[3])[grow^]` と書けます。
動的参照の要素も `Shape[dynamic^..]`、`Shape[dynamic^2]`、`Shape[dynamic^grow^]` と括弧なしで書けます。
`Shape[ref^dyn^..]` も同じ型です（[動的ディスパッチ](dyn.md)）。
`dynamic^` は配列の `[]` より先に結合するので、`dynamic^Shape[2]` も `Shape[dynamic^2]` と同じ型です。
`ref^dynamic^Shape[2]` は、その配列全体への参照になります。

## 配列型の入れ子

配列型を要素にする場合は、括弧で要素型を囲むか、外側の指定の後ろに内側の配列指定を書きます。
両者は同じ型です。

```rhat
(T[3])[2]              # 3要素の行を2個。2行×3列
T[2 [3]]               # 上と同じ型
(T[3])[grow^]          # 固定長3要素の行を並べる伸長配列
T[grow^ [3]]           # 上と同じ型
T[4 [2 [3]]]           # ((T[3])[2])[4]
```

型の位置では `T[3][2]` のような括弧なしの連続した `[]` を禁止します。
内側を先に書く旧表記 `T[[3] 2]` も拒否します。`T[2 [3]]` は外側から内側へ読み、
添字の `a[行][列]` と同じ順序になります。外側が `T[]` なら指定が空なので `T[[3]]` です。
`(T)` のように型全体を囲むだけでは意味は変わらず、`(T[3])[2]` では要素型を明示的に区切ります。
値の添字は従来どおり `a[行][列]` と書けます。型名のホバー・診断は括弧付きの基本形を使います。
フォーマッターはどちらの合法表記も保ち、括弧を削除したり別表記へ変換したりしません。

`ref^` などの要素修飾は各段階に掛かります。例えば `T[ref^max^64 [3]]` は、
固定長3要素の配列への参照を最大64個持ち、`(T[3])[ref^max^64]` と同じです。

`T[max^64 [grow^]]` と `(T[grow^])[max^64]` は同じ、行を所有するジャグ配列です。
`T[N [grow^]]` も同様に固定個数の行を所有します。
必要な独立データスタック数はコンパイル時に決定できなければなりません。
外側が `grow^`、実行時容量の `max^`、実行時長さの `[]` で、要素が所有領域を持つ形は拒否します。

## 行を所有するジャグ配列

固定長配列・静的上限付き配列の要素が所有領域を持つ場合、外側が各行の領域も所有します。
固定長の値を並べる従来の配列と、明示的な `ref^` を並べる借用配列はそのままです。

```rhat
var^d = i32^[max^8 [grow^]]{}
d.push({1, 2})
d.push({})
d[1].push(3)
let^row = d[0]       # ref^i32^[grow^]。所有する行のコピーではなく借用
row.push(4)
d.push({5})          # 既存の行の保存場所は動かない
print^(row.len, d[1][0])
```

固定長の親は、従来の固定長配列と同じく、指定個数ちょうどの行を構築します。

```rhat
var^fixed = i32^[2 [grow^]]{{}, {1, 2}}
fixed[0].push(3)
fixed[1].push(4)
print^(fixed.len, fixed[0][0], fixed[1].len)  # 2, 3, 3
```

`fixed` 自身の行数は変更できず、`push`・`pop`・`clear`・`truncate`・`append` は使えません。
`i32^[2 [grow^]]{}` は、各行を既定初期化して空の行を2行構築します。`{{}, {}}` と同じです。
初期値を1行以上指定した場合は、指定個数ちょうどの行が必要です。
行数を変える外側の操作と、`fixed[i].push(...)` による行の伸長は別です。

最初から空の行を8行用意する場合は `i32^[8 [grow^]]{}` と書けます。
`i32^[max^8 [grow^]]{}` は上限8と現在の行数が別で、`{}` 直後の行数は0です。
配列構築の `()` はサイズ・容量指定専用です。現状は `T[max^](capacity)` のみ対応しており、
`i32^[[grow^]](8)` のように所有する行数を実行時に決める指定は認めません。コピー構築には `{source...}` を使います。

- 行の記述子は外側の固定スロットに置き、要素データは行ごとのデータスタックに置きます。
  外側に生のポインターを並べるだけではなく、行の寿命と領域を外側が管理します。
- 上限付きの親の `push` は行を保存場所へ直接構築し、その参照を返します。添字も行への参照を返すため、
  `let^row = d[i]` で借用できます。外側をコピーしたり、既存の行の所有権をコピーして追加したりはできません。
- 各行は独立に伸長できます。行がさらに固定長・上限付きの所有配列である形や、所有フィールドを持つ構造体の行にも対応します。
- 必要なスタック数は、外側の固定長または静的上限と行の必要数の積として静的に予約します。
  例の配列は最大8行なので8本です。外側のスコープを抜けると全て元の先端へ戻します。
- 上限付きの親の `clear`・`truncate`・`pop` は削除する行を破棄し、その行のスタックを再利用できる状態に戻します。
  所有する行の `pop` は値を返しません。行の参照・要素の参照・スライスなどが残る状態での削除は拒否します。
- 行の構築が `try^` で中断された場合、構築済みの部分を破棄し、行の領域を戻してからハンドラーへ進みます。
  行の構築中に同じ外側配列を変更することも拒否します。
- `for^` とスライスで行を借用できます。`append` による所有する行のコピーはできません。
- 外側自身も所有値なので、構造体の所有フィールドは最後の一つ、という既存の規則が適用されます。

所有する行を持てる外側は、固定長 `N` または静的上限 `max^N` です。
N はコンパイル時の定数で、構築時に容量・長さが決まるだけでは、この条件を満たしません。
この型を含むスレッド起動引数・Channel メッセージの転送は、再構築処理が未対応のため拒否します。

## 固定長の多次元配列

`T[行数, 列数]` は固定長の矩形配列です。3次元以上も同じ順序で指定します。
各次元は通常の固定長配列と同じく、1以上1000000以下の整数定数式です。

```rhat
var^a:i32^[2, 3] = {{10, 11, 12}, {20, 21, 22}}
let^b = i32^[2, 3]{{30, 31, 32}, {40, 41, 42}}
a[1, 2] += 1
var^cube:i32^[2, 2, 2] = {{{1, 2}, {3, 4}}, {{5, 6}, {7, 8}}}
cube[1, 0, 1] := 60
```

- 型と添字は両方とも外側の次元から書きます。2次元なら行、列の順です。
- 全要素を行優先で連続配置し、最後の次元の添字が最も速く進みます。
  形状は型に含まれ、実行時のサイズ情報やポインターは値に追加しません。
- 初期値は次元ごとに波括弧を入れ子にし、各段の要素数を検査します。
- 添字は次元数と一致する個数を一組の `[]` に渡します。`a[1]` や `a[1][2]` は拒否します。
  基底式と各添字は一度ずつ左から右に評価し、各次元で境界を検査します。
  `a[0, 3]` が次の行を指すことはありません。
- `ref^a[行, 列]` による借用、要素の更新、配列全体のコピーには既存の規則を適用します。
- `a.len` は最外次元の長さです。走査とスライスも最外次元の行・部分配列を単位とし、
  `.bytes` は配列全体の連続領域を指します。

`T[2, 3]` と `(T[3])[2]` は同じ配置ですが別の型です。後者は引き続き `a[行][列]` でアクセスし、
カンマ区切りの添字は受け付けません。型を省略した `{{1, 2}, {3, 4}}` は従来どおり配列の配列です。

### 第1次元だけが伸長する多次元配列

`T[grow^, N]` は列数Nが固定で、行数だけを伸長できる矩形配列です。
`T[grow^, N, M]` のように3次元以上も指定できます。第2次元以降は固定長です。

```rhat
var^a = i32^[grow^, 3]{}
a.push({1, 2, 3})
a.push({4, 5, 6})
a[1, 2] += 1
print^(a.len, a[1, 2])  # 2, 7
```

- 固定長の行・部分配列を要素として、配列全体で1本のデータスタックを使います。
  行が増えても必要なスタック数は増えず、全要素を行優先で連続配置します。
- `push`・`pop`・`append`・`truncate`・`clear` は最外次元の行・部分配列を単位とします。
  `.len` は行数、`.bytes` は現在の全行の連続領域です。`{}` は0行で構築します。
- 添字は `a[行, 列]` と書きます。次元数の検査、各次元の境界検査、借用、走査、スライスは固定長の場合と同じです。
  行の幅を `_^` で推論する場合は `i32^[grow^, _^]{{1, 2, 3}}` と書けます。
- `T[grow^, N]` は `T[grow^ [N]]` と同じ配置ですが別の型です。
  所有配列なので全体の暗黙コピーは禁止し、関数へは `ref^` で渡します。
- `T[N, grow^]` や `T[grow^, grow^]` は拒否します。`flex^`・`max^` とカンマで次元を組み合わせる型、
  実行時の内側の形状、次元指定のスライスは未対応です。

## 固定長サイズの推論

固定長のサイズ位置に `_^` を書くと、構築式の要素列または定数回数の `repeat^` からサイズを決定します。

```rhat
var^a = i32^[_^]{0 repeat^5}                       # i32^[5]
var^b = i32^[_^, _^]{{0 repeat^3} repeat^3}        # i32^[3, 3]
var^c = i32^[2, _^]{{1, 2, 3}, {4, 5, 6}}         # i32^[2, 3]
var^d:i32^[_^ [_^]] = {{1, 2}, {3, 4}}             # i32^[2 [2]]
var^e = i32^[_^ [grow^]]{{1}, {2, 3}}              # 固定2行の所有配列
```

- 各段のサイズは独立に推論し、同じ次元を構築する全ての行で一致しなければエラーです。
- 推論後は通常の固定長型です。構築後にサイズが変わる配列にはなりません。
- 変数の型注釈や、初期値を持つフィールドの型にも書けます。関数の引数型など、構築式がない位置では推論できません。
- 空の要素列、実行時の繰り返し回数、`i32^[_^]{0 repeat^max^}` のような循環した指定は拒否します。
  `i32^[_^, 3]{{0 repeat^max^} repeat^2}` なら、外側は2、内側は明示された3で決定できます。
- `T[]` は引き続き構築時に長さを決める所有配列です。`T[]{0 repeat^5}` を `T[5]` へ置き換えません。
- `_` は通常の名前です。`T[_]` はその名前の整数定数をサイズに使い、`T[_^]` だけが推論指定です。

## 配列リテラル

L^ と同じく、要素を位置で並べた波括弧が配列です。`{name = value}` と名前で書けば構造体です。
旧来の角括弧のリテラル `[a, b]` / `[grow^; a, b]` は受け付けません。

```rhat
let^fixed = {0, 1, 2}                    # i32^[3]
var^growing = i32^[grow^]{0, 1, 2}
var^bounded = u32^[max^10]{0, 1, 2}
let^sized = i32^[]{4, 5, 6}              # 構築後に長さを変えない所有配列
let^exact = u32^[3]{0, 1, 2}
var^empty:i64^[grow^] = {}
var^also = i64^[grow^]{}
let^grid = {{1, 2}, {3, 4}}              # (i32^[2])[2]
var^values:i32^[4] = {0, 1, 2, 3}
let^refs = i32^[ref^2]{values[0], values[1]}
var^held = i32^[ref^max^10]{values[0], ref^values[1]}
```

- `T[...]{...}` は型を前に置いて明示します。型注釈もあるときは、両者が一致しなければエラーです
  （`let^ a:i32^[] = i64^[]{1}` は拒否）。
- 型のない `{a, b}` は期待型の種類と要素型に従い、期待型がなければ先頭の要素の型の固定長配列です。
  `{}` は期待型が固定長配列なら全要素の既定初期化、その他の所有配列なら空配列、構造体なら既定値での構築です。
  期待型がなければ拒否します。
- 固定長配列の `{}` は、数値を0、`bool^` を `false^`、`char^` をヌル文字、`nil^` を `nil^`、列挙型を0に初期化します。
  構造体は各フィールドの既定初期値を使い、入れ子の固定長配列は再帰的に初期化し、伸縮配列は空で構築します。
  参照・文字列・スライス・合併型など、既定初期化できない要素は明示的な初期値が必要です。
  初期値を1個以上書いた場合は、固定長の要素数ちょうどが必要です。
- `T[]{...}` の `T[]` は型としての意味のまま、構築後に長さを変えない所有配列です（C の「長さを推論する固定長配列」ではありません）。
  長さを推論する固定長配列は型のない `{...}` で書きます。
- 型の要素が `ref^` なら、値型の要素には明示的な `ref^ value` と同じ借用を補います。
  既に参照型ならそのまま格納し、参照を自動で重ねません。
- 借用には通常どおり `var^` の安定した保存場所が必要です。数値・構造体の一時値は拒否し、
  要素の寿命・借用先の縮小・`f^` からの変更制限も既存の規則で検査します。
- 型だけを値として書くこと（`let^ a = i32^[grow^]`）はできません。空なら `i32^[grow^]{}` と書きます。
- 文頭の `{` は、`let^`・`return^` などの文が続かない限り、配列・構造体のリテラルとして読みます。
  `{x = y}` は構造体のフィールド指定と読むため、比較の結果を並べるなら `{(x = y), ...}` と括弧で囲みます。
  `if^` などのヘッダーの中では、長さだけの `T[3]{...}` は本体の `{` と区別できないため使えません。
- スライスは他の保存場所を借りるため、`T[..]{...}` で新しく構築せず、範囲で取得します。
- 同じ値を n 個並べた所有配列は `T[]{value repeat^ n}` で作ります。

## スライスの書き込みと read^

スライスの扱いは `ref^T` と `ref^read^T` に揃えています。Rust の `&mut [T]` と `&[T]`、Goose の `T[:]` と `const T[:]` に相当します。

```rhat
let^sort = p^xs:i32^[..] { ... }                # 要素を書き換えられる
let^write = p^self^, data:read^u8^[..] { ... }  # 読むだけ
let^sum = f^xs:i32^[..] -> i32^{ ... }         # f^ は書いても read^ と同じ
```

- **書けるのは要素だけです。** 長さは変わりません。追加・削除は `ref^T[grow^]` です。スライスは先頭と長さしか持たないので、配列の空きも長さも知りません。
- **`p^` の引数は既定で書き込み可、`read^` で読み取り専用です。** `f^` の引数は、書き方によらず `read^` です。可変長引数 `...:T` の要素も `read^` です。
- **`read^` の規則は [`ref^read^`](read_parameters.md) と同じです。** 書き込み可から `read^` へは変換でき、逆はできません。`read^` への変換が始めた読み取り借用は保護スコープの間、元の変更を禁じます。
  引数なら呼び出しの間、局所変数や戻り値ならブロックの終わりまでです。範囲を狭めたいなら `do^{...}` で区切ります。
  中の要素に書き込み可の参照があっても、`read^` 経由では取り出せません。
- **`read^` と書き込み可が同じ配列を指す組み合わせは拒否します。** 検査はオブジェクト全体を見るので、`a[0 .. 2]` と `a[2 .. 4]` も拒否されます。
- **書き込み可どうしの重なりは許します。** `a[.. mid]` と `a[mid ..]` を同時に渡せます。`noalias` は付けていないのでメモリ安全で、Rust の `split_at_mut` にあたるものは要りません。

型を書かないスライスの種類は元で決まります。

```rhat
var^a = i32^[grow^]{1, 2}
let^b = i32^[grow^]{1, 2}
let^w = a[..]               # i32^[..]。let^ でも要素は書ける。保護もない
let^r:read^i32^[..] = a[..] # 読み取り借用。ブロックの終わりまで a を変更できない
let^s = b[..]               # read^i32^[..]。let^ の配列は書けない
let^t = "text".bytes        # read^u8^[..]。.bytes は常に read^
```

スライスはハンドルなので、`let^` か `var^` かは要素の書き込みに関係しません。`var^` は別のスライスへの差し替えを許すだけです。

`read^` のスライスを返す関数の保護は、結果を局所変数に持たなくても呼び出したブロックの終わりまで続きます（`ref^read^` と同じです）。
標準ライブラリの `HashMap.items()` と `MemoryWriter.data()` が該当します。

```rhat
print^(out.data().len)
out.clear()                 # エラー: data() の読み取り借用がこのブロックの間続く

do^{
    print^(out.data().len)
}
out.clear()                 # 通る
```

`read^` を引数に取るだけなら保護は呼び出しの間で終わるので、`file.write(buffer[..])` の後に `buffer` を変更できます。

`read^` のスライスをフィールドに持つ値は、その読み取り借用の保護スコープより長く生きられません。
ループの中で始めた借用を、ループの外の配列に保存することはできません。この場合はフィールドを修飾なしの `T[..]` にします。

`HashMap` の走査（`for^k, v in^m`）と `HashSet` の走査は読み取り借用を取りません。`HashMap<K, ref^T>` の値を取り出せるようにするためです。

## 配列長の定数式

`T[N]` と `T[max^N]` の N には、コンパイル時に値の決まる整数式を書けます。

- 整数リテラル、単項 `-`、`+ - * / %`、括弧。
- エントリーファイルのトップレベルの `let^` で、整数型（または型注釈なし）かつ初期値がこの規則の定数式であるもの。
- モジュールの定数（`import^` したモジュールの `public^ let^` を含む）。
- `var^`・関数の引数・ローカル変数は定数ではありません。トップレベルの名前をローカルが隠していればそのローカルを指すので、定数にはなりません。
- 値は 1〜1000000 で、外れればエラーです。ゼロ除算や途中の桁あふれ（2^40 超）は定数として扱いません。

```rhat
let^WIDTH:i64^ = 80
let^DEPTH:i64^ = 80
var^column_top:i64^[WIDTH * DEPTH] = {0 repeat^ WIDTH * DEPTH}
var^message:u8^[max^ 100] = {}
```

式の中の `T[N]{...}` の形（`i32^[3]{1, 2, 3}`）は、`a[i]` の添字と区別するため長さが整数リテラルのときに限ります。
定数名の長さは型注釈か、`repeat^` の推論で使います。

## 構築後に長さが変わらない所有配列 T[]

```rhat
let^n:i64^ = 100
var^values = i32^[]{0 repeat^ n}
var^zeros:i64^[] = {0 repeat^ n}     # 型注釈だけでもよい
values[0] := 42
let^copied:i32^[] = {values...}
let^tail = i32^[]{values[10 ..]...}
var^empty:i32^[] = {}
var^literal:i32^[] = {1, 2, 3}
```

- `{value repeat^ n}` は初期値と `i64^` の要素数を左から順に一度ずつ評価し、初期値を各要素へコピーします。
  要素数が0でも初期値は評価します。負数・保存領域を超える長さは実行時エラーです。
  書き込み前に保存可能な要素数を確認するため、バイト数の乗算の桁あふれは起きません。
- 固定長配列の `repeat^max^` は、その段の初期化先の要素数を繰り返し回数に使います。
  `u8^[2 [3]]{{0 repeat^max^} repeat^max^}` は `u8^[2 [3]]{{0 repeat^3} repeat^2}` と同じです。
  型注釈・フィールド型・戻り値型からの指定も使えます。初期値を一度評価してコピーする規則は通常の `repeat^` と同じです。
  固定長の初期化先がない場合や、`T[]`・`T[grow^]`・`T[max^N]`・`T[max^]` では拒否します。
  所有領域を持つ要素のコピーを許可するものではありません。
- `{source...}`は同じ要素型の固定長・上限付き・所有配列・スライスから、新しい所有領域へコピーします。
  配列全体への参照も受け付けます。スカラー要素のコピーは元の配列の寿命から独立します。
- `repeat^` と `...` は波括弧の唯一の要素として書き、ほかの要素とは並べません。
  型は `T[...]{...}` か代入先から決まり、`repeat^` は `T[N]`・`T[]`・`T[grow^]`・`T[flex^]` を、
  `...` は所有配列を作れます（上限付き・`T[max^]` は作れません）。`T[N]` を作る `repeat^` の要素数は値が N の定数式です。
- 型も代入先もない `{value repeat^ n}` は、n が定数式なら固定長の `T[n]`、そうでなければ `T[]` です（T は value の型）。
  所有領域を持つ要素は固定長へコピーできないため `T[]` になります。`{source...}` は型か代入先が必要です。

  ```rhat
  let^CHUNKS:i64^ = 5
  var^meshes = {Mesh{} repeat^CHUNKS * CHUNKS}    # Mesh[25]
  var^scratch = {0.0 repeat^count}                # count が変数なら f64^[]
  ```

  配列構築の `()` はサイズ・容量指定専用です。コピー構築の `T[](source)` と旧来の `T[](n, value)` は受け付けません。
  現状、`()` で構築できるのは `T[max^](capacity)` のみです。
- 空の所有配列は `T[]{}` です。参照要素なら `Node[ref^]{ref^ node repeat^ n}` / `Node[ref^]{source...}` と書けます。
- `push`・`pop`・`append`・`clear`・`truncate` は使えません。`len`・添字・範囲スライス・`bytes` は使えます。
- 所有領域を持つため、暗黙のコピーと再代入はできません。引数には `ref^ T[]` で渡し、
  結果は呼び出し側の保存先へ直接構築します。要素内の参照も通常の寿命検査に参加します。
- 要素は非所有・固定サイズの値に限定します。実行時サイズの要素をインラインに詰める
  Goose の可変サイズ配置は[採用しません](#可変サイズ配置を採用しない理由)。構造体の所有フィールドは既存の伸長配列と同じく最後に限ります。

## 構築時に容量を決める所有配列 T[max^]

```rhat
var^lines = Line[max^](n)
var^more:Line[max^] = {max^n}       # 型注釈だけでもよい
var^also = Line[max^]{max^n}
lines.push(Line{})
let^fill = p^out:ref^Line[max^] { out.push(Line{}) }
```

- `T[max^](capacity)`・`{max^capacity}`・`T[max^]{max^capacity}` は `i64^` の容量を評価し、長さ0の配列を作ります。
  容量ぶんの要素領域を構築時にデータスタック上へ確保し、以後は動かしません。負数・保存領域を超える容量は実行時エラーです。
- `push`・`pop`・`append`・`clear`・`truncate`・添字・範囲スライス・`len`・`bytes` を持ちます。
  容量を超える `push`・`append` は `T[max^N]` と同じく実行時エラー（bounded array is full）です。
- 縮小は論理長だけを変え、領域は返しません。`grow^` と同じく、縮小後の要素への参照も安全です。
- 要素を並べたリテラル（`{a, b}`）や `repeat^`・`...` では作れません。
- 所有の規則は `T[]` と同じです。暗黙のコピー・再代入はできず、引数は `ref^ T[max^]` で渡します。
  要素は非所有・固定サイズの値に限ります。
- 表現は伸長配列と同じ `{ data, length, stack }` です。構築時に要素領域の直前へ専用の 32 バイトのスタック記録を置き、
  `stack` はそれを指します。記録の上限は要素領域の終端なので、伸長配列の push・append の検査がそのまま容量の検査になります。
  記録の base は null で、上限に達したときの失敗をデータスタック溢れと区別します。
- Goose の `T[varint]`（可変幅の長さ欄）は採用しません。R^ の配列は長さを記述子に持つため、
  長さ欄を縮めても本体が別の領域にある限り節約にならないからです。

## 可変サイズ配置を採用しない理由

Goose は可変サイズの部分を持つレコードを一続きのメモリに詰めます（`u8[varint]`、`Item[varint]`）。R^ はこの配置を採用しません。

Goose の利点は、メモリ密度、順に読むときの局所性、バイト列のまま保存・送信できることの3つです。
R^ の保存・通信は、ストリームの読み書きを型ごとに定義する方針なので（[io.md](io.md)）、3つ目は目的にしません。
残りの2つには、次の代償があります。

- 要素の大きさが一定でなくなり、添字で引けません。順にたどるか、別の索引配列を持つことになります。
- 構築後の要素は伸ばせません。後ろに次の要素が詰まっているからです。
- 「型の大きさは一定」という前提が崩れ、配置・添字・要素への参照・合併型・ジェネリクス・`dyn^` のすべてに影響します。

同じレコードは、ビューと置き場で表現します。`grow^` の領域は動かないので、ビューを保存しても安全で、確保の回数も増えず、添字も使えます。代償はビュー1本につき16バイトです。

```rhat
def^Item { self^{ sku:string^, qty:i32^} }
def^Order { self^{ customer:string^, items:Item[..] } }

var^text = std.text.Builder{}   # 文字列の置き場
var^items = Item[grow^]{}       # Item の置き場
var^orders = Order[grow^]{}     # 添字で引ける
```

### 見直す条件

小さなレコードが数百万件あり、ビューの16バイトが支配的であると計測で分かったときに見直します。その場合も、言語機能の前にライブラリで次を試します。

- 置き場の位置と長さだけを持つ 8 バイトの参照（`offset:u32^, len:u32^`）。読み出しは境界検査つきになります。
- 通信プロトコルの可変長整数は、`std.io` の読み書きの関数として足します。言語機能は要りません。

これらで足りないと実測で示せたときに、言語機能を再検討します。

## 上限付き配列 T[max^N]

`T[max^N]` は、長さ（`i64^`）と N 個分の要素の領域をそのまま値の中に持つ配列です。`grow^` と同じく
`push`・`pop`・`clear`・`truncate`・`append`・添字・スライス・`len`・`bytes` を持ちます。

```rhat
def^World {
    self^{ actors:Actor[max^512] = {}, lines:Line[max^2048] = {}, log:Event[grow^] = {} }
}
```

- 要素が非所有なら、所有領域を持たないので構造体に何本でも置けます。伸長配列のフィールドは一つで最後、という制約（データスタックのモデル）とは別です。
  値としてコピーでき、関数の結果にもなります（大きさは 8 + N × 要素の大きさ）。
- `push` と `append` は上限を超えると「bounded array is full」で終了します。添字は今の長さまでを検査します。
- 長さより後ろの要素は読まれないので、`{}` は長さを 0 にするだけで、領域を初期化しません。
- 参照を含む要素の寿命は、固定長配列と同じく配列の値の由来として検査します。
  要素が所有領域を持つ場合は、[行を所有するジャグ配列](#行を所有するジャグ配列)として扱います。

## grow^ と flex^ の縮小

どちらも `push`・`append`・添字・スライス・`pop`・`clear`・`truncate` を持ちます。違いは縮小時の保存領域です。

- `grow^`: 縮小は論理長だけを変え、保存領域の最大末尾を配列の寿命まで保持します。既存の参照は同じスロットを指し続けるため、
  参照の扱いに制限はありません。
- `flex^`: 縮小のたびにデータスタックの先端を新しい末尾まで戻し、空いた領域が 4 MiB を超えると、
  新しい末尾の上に 1 MiB を残してページを OS に返します（Windows は `VirtualFree` の decommit、ほかは `madvise(MADV_DONTNEED)`）。
  寿命の長いキューやバッファのピーク時のメモリを、配列を破棄せずに返せます。

`flex^` の縮小は、縮める保存領域を指しうる値が残っているとコンパイルエラーです。

```rhat
var^q:Job[flex^] = {}
let^first = ref^q[0]
q.pop()                      # 拒否: 'first' may refer into it
do^{ let^r = ref^q[0] use(r) }
q.pop()                      # 可: r のスコープは終わっている
```

- 対象はスコープ内の変数と、評価中の式で先に評価した値（前の引数・構築中のリテラルの要素）です。
- 由来と型で判定します。配列全体への参照（`ref^ T[flex^]`）や、要素の一部になりえない型への参照は対象外です。
- 呼び出し先が引数を通じて縮める場合も同じ検査を行います。縮めるかどうかは具体化ごとの要約で、
  呼び出しを重ねても伝わります。再帰で要約が確定していない呼び出しは縮めるものとみなします。
- R^ は参照の由来をすべて追跡しているため、Goose の「内部への参照は変数にだけ置ける」という制限はありません。
  構造体や配列に入れた参照も、その変数の由来として検査されます。
- `flex^` のフィールドを持つ型は `dyn^` に変換できません（動的な呼び出しに縮小の要約がないため）。

参照の検査はスコープ単位です。最後の使用以降も、スコープが終わるまでは生存しているものとみなします。

## 範囲

- `n to^ m`：両端を含む `[n, m]`。数えるループの `to^` と同じ意味です。
- `n .. m`：終端を含まない `[n, m)`。

範囲は `range^` の値でもあり、変数に入れたり関数に渡したりして `xs[r]` で使えます（[範囲](ranges.md)）。

`..` は範囲専用です。L^ で連結に使う演算子は R^ では `::`（オーバーロード専用、組み込みの意味なし）に移しました。

## 配列のバイト列表示

`a.bytes` は、固定長配列・伸長配列・スライスの全要素を `u8^[..]` のビューとして見せます（`s.bytes` と同じ書き方）。
頂点バッファやファイルへの書き出しなど、C に生のバイトを渡すときに使います。コピーはせず、長さは要素数 × 要素の大きさです。

```rhat
let^vertices:f32^[6] = {0.0, 0.5, -0.5, -0.5, 0.5, -0.5}
let^raw = vertices.bytes           # u8^[..]、24 バイト
```

- 要素は数値型（`bool^`・`char^`・`enum^` を除く）と、それだけでできた配列・`def^` に限ります。
  どのビットの並びも有効な値になる型だけなので、バイトの見え方は安全です。参照・文字列・合併型・伸長配列を含む型はエラーです。
- ビューは読み取り専用で、元の配列を借ります。他のスライスと同じく、束縛のない一時配列には使えません。
- バイトの並びはホストのバイト順です（0.1 は x86-64 のリトルエンディアン）。構造体のパディングの内容は不定です。

## スライス

添字に範囲を書くと、コピーしないビュー `T[..]` を作ります。`.slice(start, count)` は廃止しました。

```rhat
let^head = values[0 .. 3]        # 0, 1, 2
let^tail = values[3 ..]          # 3 から末尾まで
let^front = values[.. 3]         # 先頭から 2 まで
let^both = values[1 to^3]        # 1, 2, 3
```

`a[i .. i]` は空のスライス、`a[..]` は全体です。`to^` は両端が必要です。
開始・終端は i64^ で、この順に一度だけ評価します。負の開始・開始 > 終端・範囲外は実行時に診断します。
`a[3 to^2]` は空です（数えるループの空範囲と同じ）。`to^` の終端 + 1 の桁あふれも範囲外になります。
`?[lo .. hi]` は `?[]` と同じく、受け手が nil なら連鎖全体を nil にします。
スライスは呼び出しではないため、それだけでは式文になりません。
固定長配列・伸長配列・スライスに使えます。`string^` は `[]` を持たないので、バイトは `s.bytes[a .. b]`（`u8^[..]`）、
部分文字列は `s.slice(a .. b)`（`string^`）で切ります（[文字列と文字](strings.md)）。
