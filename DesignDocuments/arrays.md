# 配列の種類・リテラル・スライス

配列の種類・容量・要素の参照修飾は型の後ろの `[]` にまとめます。
旧型構文の前置 `grow^ T[]`・`flex^ T[]`・`T[:]`、Goose の上限付き配列 `T[..N]`、旧スライス型 `T[slice^]` は受け付けません。
値は構造体と同じく波括弧で書き、`T[...]{a, b}` または期待型に従う `{a, b}` です。
式のスライス取得には引き続き範囲表記 `values[start .. end]` を使います。

## 配列の種類

種類はハット識別子で指定します。

- `T[N]`：固定長配列。型のない `{a, b, c}` は `T[3]` です。N は[整数の定数式](#配列長の定数式)でも書けます。
- `T[]`：構築時に長さを決め、その後は長さを変更しない所有配列。要素の書き換えは可能です。
- `T[grow^]`：伸長のみの配列。旧記法 `T[>..]` を置き換えます。
- `T[flex^]`：伸長・縮小の両方ができる配列。Goose の `T[>..<]` に相当します。
- `T[max^N]`：上限付き配列。最大 N 個の要素を値の中に持ち、所有領域を持ちません。
- `T[max^]`：容量を構築時に決める所有配列。その容量内で伸縮します。Goose の `T[..]` に相当し、`T[max^](capacity)` で作ります。
- `T[..]`：借用スライス。他の配列の要素の並びを指すビューで、所有も伸縮もしません。Goose の `T[:]` に相当します。
  式の `a[..]`（全体）や `a[i .. j]` が作る値の型であり、どの種類の配列からも取得できるため、読むだけの引数に向きます。
  配列の種類ごとの操作（`push` など）が要るなら、配列全体への参照 `ref^ T[grow^]` を使います。

```rhat
var^ nodes = Node[grow^]{Node{}, Node{}, Node{}}
var^ queue:Job[flex^] = {}
let^ make = p^ pool:ref^ Node[grow^] -> i32^ { ... }
```

外側の `ref^` は後続する型全体への参照です。`ref^ Node[grow^]` は伸長配列全体への参照、
`Node[ref^ grow^]` は参照の伸長配列です。`[]` 内では要素の `ref^`、次に種類・容量の順に書きます。
`Node[ref^ max^10]` は `(ref^ Node)[max^10]` と同じ型です。
参照の重ね掛けは `Node[ref^^ max^10]`、配列の入れ子は `Node[3][grow^]` と書けます。

## 配列リテラル

L^ と同じく、要素を位置で並べた波括弧が配列です。`{name = value}` と名前で書けば構造体です。
旧来の角括弧のリテラル `[a, b]` / `[grow^; a, b]` は受け付けません。

```rhat
let^ fixed = {0, 1, 2}                    # i32^[3]
var^ growing = i32^[grow^]{0, 1, 2}
var^ bounded = u32^[max^10]{0, 1, 2}
let^ sized = i32^[]{4, 5, 6}              # 構築後に長さを変えない所有配列
let^ exact = u32^[3]{0, 1, 2}
var^ empty:i64^[grow^] = {}
var^ also = i64^[grow^]{}
let^ grid = {{1, 2}, {3, 4}}              # i32^[2][2]
var^ values:i32^[4] = {0, 1, 2, 3}
let^ refs = i32^[ref^ 2]{values[0], values[1]}
var^ held = i32^[ref^ max^10]{values[0], ref^ values[1]}
```

- `T[...]{...}` は型を前に置いて明示します。型注釈もあるときは、両者が一致しなければエラーです
  （`let^ a:i32^[] = i64^[]{1}` は拒否）。
- 型のない `{a, b}` は期待型の種類と要素型に従い、期待型がなければ先頭の要素の型の固定長配列です。
  `{}` は期待型が配列なら空配列、構造体なら既定値での構築です。期待型がなければ拒否します。
- `T[]{...}` の `T[]` は型としての意味のまま、構築後に長さを変えない所有配列です（C の「長さを推論する固定長配列」ではありません）。
  長さを推論する固定長配列は型のない `{...}` で書きます。
- 型の要素が `ref^` なら、値型の要素には明示的な `ref^ value` と同じ借用を補います。
  既に参照型ならそのまま格納し、参照を自動で重ねません。
- 借用には通常どおり `var^` の安定した保存場所が必要です。数値・構造体の一時値は拒否し、
  要素の寿命・借用先の縮小・`f^` からの変更制限も既存の規則で検査します。
- 型だけを値として書くこと（`let^ a = i32^[grow^]`）はできません。空なら `i32^[grow^]{}` と書きます。
- 文頭の `{` は、`let^`・`return^` などの文が続かない限り、配列・構造体のリテラルとして読みます。
  `{x = y}` は構造体のフィールド指定と読むため、比較の結果を並べるなら `{(x = y), ...}` と括弧で囲みます。
  `if^` などのヘッダーの中では、長さだけの `T[3]{...}` は本体の `{` と区別できないため使えません。
- スライスは他の保存場所を借りるため、`T[..]{...}` で新しく構築せず、範囲で取得します。
- 同じ値を n 個並べた所有配列は `T[]{value repeat^ n}` で作ります。

## 配列長の定数式

`T[N]` と `T[max^N]` の N には、コンパイル時に値の決まる整数式を書けます。

- 整数リテラル、単項 `-`、`+ - * / %`、括弧。
- エントリーファイルのトップレベルの `let^` で、整数型（または型注釈なし）かつ初期値がこの規則の定数式であるもの。
- モジュールの定数（`import^` したモジュールの `public^ let^` を含む）。
- `var^`・関数の引数・ローカル変数は定数ではありません。トップレベルの名前をローカルが隠していればそのローカルを指すので、定数にはなりません。
- 値は 1〜1000000 で、外れればエラーです。ゼロ除算や途中の桁あふれ（2^40 超）は定数として扱いません。

```rhat
let^ WIDTH:i64^ = 80
let^ DEPTH:i64^ = 80
var^ column_top:i64^[WIDTH * DEPTH] = {0 repeat^ WIDTH * DEPTH}
var^ message:u8^[max^ 100] = {}
```

式の中の `T[N]{...}` の形（`i32^[3]{1, 2, 3}`）は、`a[i]` の添字と区別するため長さが整数リテラルのときに限ります。
定数名の長さは型注釈か、`repeat^` の推論で使います。

## 構築後に長さが変わらない所有配列 T[]

```rhat
let^ n:i64^ = 100
var^ values = i32^[]{0 repeat^ n}
var^ zeros:i64^[] = {0 repeat^ n}     # 型注釈だけでもよい
values[0] := 42
let^ copied:i32^[] = {values...}
let^ tail = i32^[]{values[10 ..]...}
let^ also = i32^[](values)            # T[](source) も使える
var^ empty:i32^[] = {}
var^ literal:i32^[] = {1, 2, 3}
```

- `{value repeat^ n}` は初期値と `i64^` の要素数を左から順に一度ずつ評価し、初期値を各要素へコピーします。
  要素数が0でも初期値は評価します。負数・保存領域を超える長さは実行時エラーです。
  書き込み前に保存可能な要素数を確認するため、バイト数の乗算の桁あふれは起きません。
- `{source...}`（または `T[](source)`）は同じ要素型の固定長・上限付き・所有配列・スライスから、新しい所有領域へコピーします。
  配列全体への参照も受け付けます。スカラー要素のコピーは元の配列の寿命から独立します。
- `repeat^` と `...` は波括弧の唯一の要素として書き、ほかの要素とは並べません。
  型は `T[...]{...}` か代入先から決まり、`repeat^` は `T[N]`・`T[]`・`T[grow^]`・`T[flex^]` を、
  `...` は所有配列を作れます（上限付き・`T[max^]` は作れません）。`T[N]` を作る `repeat^` の要素数は値が N の定数式です。
- 型も代入先もない `{value repeat^ n}` は、n が定数式なら固定長の `T[n]`、そうでなければ `T[]` です（T は value の型）。
  所有領域を持つ要素は固定長へコピーできないため `T[]` になります。`{source...}` は型か代入先が必要です。

  ```rhat
  let^ CHUNKS:i64^ = 5
  var^ meshes = {Mesh{} repeat^ CHUNKS * CHUNKS}   # Mesh[25]
  var^ scratch = {0.0 repeat^ count}               # count が変数なら f64^[]
  ```

  旧来の `T[](n, value)` は廃止しました。
- 空の所有配列は `T[]{}` です。参照要素なら `Node[ref^]{ref^ node repeat^ n}` / `Node[ref^]{source...}` と書けます。
- `push`・`pop`・`append`・`clear`・`truncate` は使えません。`len`・添字・範囲スライス・`bytes` は使えます。
- 所有領域を持つため、暗黙のコピーと再代入はできません。引数には `ref^ T[]` で渡し、
  結果は呼び出し側の保存先へ直接構築します。要素内の参照も通常の寿命検査に参加します。
- 現段階では要素を非所有・固定サイズの値に限定します。実行時サイズの要素をインラインに詰める
  Goose の可変サイズ配置には対応しません。構造体の所有フィールドは既存の伸長配列と同じく最後に限ります。

## 構築時に容量を決める所有配列 T[max^]

```rhat
var^ lines = Line[max^](n)
var^ more:Line[max^] = {max^ n}       # 型注釈だけでもよい
var^ also = Line[max^]{max^ n}
lines.push(Line{})
let^ fill = p^ out:ref^ Line[max^] { out.push(Line{}) }
```

- `T[max^](capacity)`・`{max^ capacity}`・`T[max^]{max^ capacity}` は `i64^` の容量を評価し、長さ0の配列を作ります。
  容量ぶんの要素領域を構築時にデータスタック上へ確保し、以後は動かしません。負数・保存領域を超える容量は実行時エラーです。
- `push`・`pop`・`append`・`clear`・`truncate`・添字・範囲スライス・`len`・`bytes` を持ちます。
  容量を超える `push`・`append` は `T[max^N]` と同じく実行時エラー（bounded array is full）です。
- 縮小は論理長だけを変え、領域は返しません。`grow^` と同じく、縮小後の要素への参照も安全です。
- 要素を並べたリテラル（`{a, b}`）や `repeat^`・`...` では作れません。
- 所有の規則は `T[]` と同じです。暗黙のコピー・再代入はできず、引数は `ref^ T[max^]` で渡します。
  要素は非所有・固定サイズの値に限ります。
- 表現は伸長配列と同じ `{ data, length, stack }` です。構築時に要素領域の直前へ専用の 32 バイトのスタック記録を置き、
  `stack` はそれを指します。記録の上限は要素領域の終端なので、伸長配列の push・append の検査がそのまま容量の検査になります。
  記録の base は null で、上限に達したときの失敗をデータスタック溢れと区別します。
- Goose の `T[varint]`（可変幅の長さ欄）は採用しません。R^ の配列は長さを記述子に持つため、
  インライン表現を導入するまで長さ欄を縮める利点がないからです。

## 上限付き配列 T[max^N]

`T[max^N]` は、長さ（`i64^`）と N 個分の要素の領域をそのまま値の中に持つ配列です。`grow^` と同じく
`push`・`pop`・`clear`・`truncate`・`append`・添字・スライス・`len`・`bytes` を持ちます。

```rhat
def^ World {
    self^{ actors:Actor[max^512] = {}, lines:Line[max^2048] = {}, log:Event[grow^] = {} }
}
```

- 所有領域を持たないので、構造体に何本でも置けます。伸長配列のフィールドは一つで最後、という制約（データスタックのモデル）とは別です。
  値としてコピーでき、関数の結果にもなります（大きさは 8 + N × 要素の大きさ）。
- `push` と `append` は上限を超えると「bounded array is full」で終了します。添字は今の長さまでを検査します。
- 長さより後ろの要素は読まれないので、`{}` は長さを 0 にするだけで、領域を初期化しません。
- 要素は固定長の値に限ります（伸長配列は入れられません）。参照を含む要素の寿命は、固定長配列と同じく配列の値の由来として検査します。

## grow^ と flex^ の縮小

どちらも `push`・`append`・添字・スライス・`pop`・`clear`・`truncate` を持ちます。違いは縮小時の保存領域です。

- `grow^`: 縮小は論理長だけを変え、保存領域の最大末尾を配列の寿命まで保持します。既存の参照は同じスロットを指し続けるため、
  参照の扱いに制限はありません。
- `flex^`: 縮小のたびにデータスタックの先端を新しい末尾まで戻し、空いた領域が 4 MiB を超えると、
  新しい末尾の上に 1 MiB を残してページを OS に返します（Windows は `VirtualFree` の decommit、ほかは `madvise(MADV_DONTNEED)`）。
  寿命の長いキューやバッファのピーク時のメモリを、配列を破棄せずに返せます。

`flex^` の縮小は、縮める保存領域を指しうる値が残っているとコンパイルエラーです。

```rhat
var^ q:Job[flex^] = {}
let^ first = ref^ q[0]
q.pop()                      # 拒否: 'first' may refer into it
do^{ let^ r = ref^ q[0] use(r) }
q.pop()                      # 可: r のスコープは終わっている
```

- 対象はスコープ内の変数と、評価中の式で先に評価した値（前の引数・構築中のリテラルの要素）です。
- 由来と型で判定します。配列全体への参照（`ref^ T[flex^]`）や、要素の一部になりえない型への参照は対象外です。
- 呼び出し先が引数を通じて縮める場合も同じ検査を行います。縮めるかどうかは具体化ごとの要約で、
  呼び出しを重ねても伝わります。再帰で要約が確定していない呼び出しは縮めるものとみなします。
- R^ は参照の由来をすべて追跡しているため、Goose の「内部への参照は変数にだけ置ける」という制限はありません。
  構造体や配列に入れた参照も、その変数の由来として検査されます。
- `flex^` のフィールドを持つ型は `dyn^` に変換できません（動的な呼び出しに縮小の要約がないため）。

参照の検査はスコープ単位です。最後の使用以降も、スコープが終わるまでは生存しているものとみなします。

## 範囲

- `n to^ m`：両端を含む `[n, m]`。数えるループの `to^` と同じ意味です。
- `n .. m`：終端を含まない `[n, m)`。

範囲は `range^` の値でもあり、変数に入れたり関数に渡したりして `xs[r]` で使えます（[範囲](ranges.md)）。

`..` は範囲専用です。L^ で連結に使う演算子は R^ では `::`（オーバーロード専用、組み込みの意味なし）に移しました。

## 配列のバイト列表示

`a.bytes` は、固定長配列・伸長配列・スライスの全要素を `u8^[..]` のビューとして見せます（`s.bytes` と同じ書き方）。
頂点バッファやファイルへの書き出しなど、C に生のバイトを渡すときに使います。コピーはせず、長さは要素数 × 要素の大きさです。

```rhat
let^ vertices:f32^[6] = {0.0, 0.5, -0.5, -0.5, 0.5, -0.5}
let^ raw = vertices.bytes          # u8^[..]、24 バイト
```

- 要素は数値型（`bool^`・`char^`・`enum^` を除く）と、それだけでできた配列・`def^` に限ります。
  どのビットの並びも有効な値になる型だけなので、バイトの見え方は安全です。参照・文字列・合併型・伸長配列を含む型はエラーです。
- ビューは読み取り専用で、元の配列を借ります。他のスライスと同じく、束縛のない一時配列には使えません。
- バイトの並びはホストのバイト順です（0.1 は x86-64 のリトルエンディアン）。構造体のパディングの内容は不定です。

## スライス

添字に範囲を書くと、コピーしないビュー `T[..]` を作ります。`.slice(start, count)` は廃止しました。

```rhat
let^ head = values[0 .. 3]       # 0, 1, 2
let^ tail = values[3 ..]         # 3 から末尾まで
let^ front = values[.. 3]        # 先頭から 2 まで
let^ both = values[1 to^ 3]      # 1, 2, 3
```

`a[i .. i]` は空のスライス、`a[..]` は全体です。`to^` は両端が必要です。
開始・終端は i64^ で、この順に一度だけ評価します。負の開始・開始 > 終端・範囲外は実行時に診断します。
`a[3 to^ 2]` は空です（数えるループの空範囲と同じ）。`to^` の終端 + 1 の桁あふれも範囲外になります。
`?[lo .. hi]` は `?[]` と同じく、受け手が nil なら連鎖全体を nil にします。
スライスは呼び出しではないため、それだけでは式文になりません。
固定長配列・伸長配列・スライスに使えます。`string^` は `[]` を持たないので、バイトは `s.bytes[a .. b]`（`u8^[..]`）、
部分文字列は `s.slice(a .. b)`（`string^`）で切ります（[文字列と文字](strings.md)）。
