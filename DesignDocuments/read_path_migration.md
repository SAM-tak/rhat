# read^ を経路ごとの変更権限に限定する移行計画

## 決定と実装状態

2026-11-10 の決定。`read^` は、その参照・スライスを経由する変更を禁止する指定とする。
別の変更可能な参照や捕捉変数から、同じ領域を変更することは許す。
参照先の値が一定であること、別名参照がないこと、並行アクセスが安全であることは保証しない。

この計画に沿って移行を実装した。現行仕様は [read_parameters.md](read_parameters.md) を参照。
以下の「現状」は調査時点の旧実装を指し、末尾に実装結果を記録する。
`append^`、範囲の非重複注釈、Goose と同じ読み取り専用性による関数の特殊化は追加しない。

## 維持する意味

- `ref^read^T`・`read^T[..]`・読み取り専用の動的参照は維持する。
- 変更可能から読み取り専用への変換を許し、逆方向は拒否する。
- コピー・再借用・フィールド・配列・返却・動的呼び出しで、読み取り経路から変更権限を取り出せないようにする。
  既存の「読み取り経路から変更可能な参照を含む値をコピーできない」規則も維持する。
  内部参照を辿る際の制約を浅くする変更は、今回に含めない。
- `let^` 自身の保存領域の変更禁止と、`f^` の効果制限は維持する。
- 通常の参照の寿命・所有・型安全性は、`read^` の有無に関係なく守る。
- 読み取り参照だけのために設けていた保護スコープと、その外への保存・返却禁止は廃止する。
  実際の参照先が十分長命なら、内側のブロックで読み取り専用に変換した参照も外へ渡せる。
  内側のローカル値そのものを指す参照は、従来どおり外へ出せない。

## 現状の実装と変更点

| 対象 | 現状 | 移行時の扱い |
|---|---|---|
| `src/borrow.c` の `ReadBorrow`・`ReadCall` | レキシカルな領域保護と引数間の競合伝播 | 保護専用の状態・処理を削除 |
| `src/sema.h` の `Root`・`Context`、`src/rhat.h` の `Instance` | 読み取り保護境界・呼び出し間の競合を保持 | 保護用のメンバーだけを削除 |
| `src/borrow.c` の `flow_store`・`flow_call` 等 | 参照の保存先・戻り値の由来を要約 | 維持し、読み取り参照も通常の寿命で扱う |
| `src/sema.c` の `store_check`・`copy_to` 等 | 権限・寿命・読み取り競合を検査 | 権限と寿命を維持し、読み取り競合だけを除去 |
| `src/sema.c` の `shrink_check` 等 | 縮小・要素破棄による参照の無効化を検査 | 維持し、読み取り参照も対象になることを検証 |
| `forget_roots` と型推論側の事実管理 | 書き込み・呼び出し後に型の絞り込みを無効化 | 維持し、必要な別名経路を補強 |

`read_write_check` は一括削除しない。同じ関数の先頭に、構築中の所有行と同じ配列への
書き込みを拒否する処理がある。この検査は領域保護とは別の安全性検査として残す。
`read_validate` も一括削除しない。後半の読み取り競合解決のほか、静的状態の使用伝播、
スレッド入口・外部公開関数、間接呼び出しと参照保存要約の検査を含んでいる。
`type_reads`・`type_writes` は呼び出し箇所ごとに用途を確認し、保護専用の利用だけを除く。
64 引数制限も、読み取り競合に固有のものだけを廃止し、参照の流れ等の上限は維持する。

## 追加・補強する可能性がある検査

以下は調査で確認した監査対象であり、すべてに新規実装が必要と確認済みという意味ではない。
既存検査で防げるものは回帰テストで固定し、不足するものだけを補う。
不正な参照の生成・使用を防ぐ検査であり、読み取り先への一般的な変更禁止は復活させない。

### 1. 型の絞り込みとユニオン内部への参照

優先度は最も高い。`fits^`・nil 判定の後でも、別名参照・別引数・捕捉変数・後続引数の評価から
同じユニオンの変種が変わりうる。変更前の判定を使って、変更後の領域を別の型として読ませない。

現状は `forget_roots` が変数・パスの絞り込みを無効化する。
通常の選択肢の取り出しは `case_value` がコピーし、所有値・Disposable はその場への参照になる。
また、コピーの IR スロットが実際に独立した保存領域になるかも確認する。

確認・対処する内容:

- `read^` 由来でも、別名からの変更後に絞り込みを破棄する。
  推論側と IR 構築側で、同じ式の型判断が食い違わないようにする。
- 関数の別引数が実際には同じ場所を指す場合も扱う。異なる仮引数の root を別物と仮定して
  判定を残していないか確認し、不明なら変更可能な呼び出しで関連する事実を保守的に破棄する。
- すでに取り出したユニオン内部への参照は、後から絞り込みを破棄するだけでは救えない。
  内部参照が生きている間の変種差し替えを拒否するか、独立した安全なコピーにする。
  コピーできない型はコピーで対処しない。必要なら `read^` と独立した内部参照の由来を追加する。
- `I_CASE_AT`・`I_CASE_GET` と、型検査の省略条件を確認する。
  参照の取り出し時だけの実行時タグ検査では、取り出した後の変種変更は防げない。

受け入れ条件は「判定後の別名変更を拒否する、再判定を要求する、またはコピーを読む」のいずれかで、
古い型の前提によるアクセスが残らないこと。

### 2. 保存領域の回収、所有行と要素の破棄

`flex^` の縮小、所有行を持つ配列の縮小、Disposable 要素の除去では、
アドレスの数値が変わらなくても参照先の有効性が失われる可能性がある。

- `shrink_check`・`shrink_argument` と `Instance.shrinks` 等の要約を維持する。
- 読み取り参照・スライス・動的参照・それらを含む構造体や配列も、生きている内部参照として数える。
- ローカル変数だけでなく、評価中の前の引数や構築途中の値も対象にする。
- 別引数・ラッパー・再帰・捕捉・静的状態を経由する縮小や破棄でも検査が届くか確認する。
  間接呼び出しで要約が使えない経路の既存制限は緩めない。
- 要素やフィールドの代入が旧値を解放する場合も確認する。特にユニオンの変種変更や
  所有値の置き換えで、内部参照を無効化する経路があれば、縮小と同様の独立した検査を設ける。

非所有・非 Disposable の `grow^` 要素については、論理長を縮めても保存領域を保持する既存仕様を維持する。
残ったスライスから旧スロットを読むことや、再追記で値が変わることは、読み取り保護の違反にはしない。
実装がスロットを初期化済みのまま保持することと、要素型の不変条件を壊さないことを確認する。

### 3. 参照を保持する値の差し替えと由来の更新

読み取り参照で見ている構造体の参照フィールドが、別経路から差し替えられる場合を扱う。
変更前に解析した参照先だけを使うと、変更後に読み出す参照の寿命を誤る可能性がある。

- `store_check`・`flow_call` の由来の合併、分岐の合流、ループの固定点計算を維持する。
- 既存の別名参照から後でフィールドを読み直す場合も、差し替え後の候補を落とさないか確認する。
- 「差し替え前にコピーした参照」と「差し替え後に同じ保存場所から読む参照」を区別する。
  安全側への候補の合併は許すが、古い候補だけに固定しない。
- 読み取り専用への変換を経由して、短命な参照を長命な保存先へ書けないことを検証する。
  関数の別引数が同じ保存場所を指す場合、関数内部の保存・返却の順序も確認する。
- 保護境界を削除しても、実際の所有者の寿命を表す root は残す。

不足がある場合は、参照を保持する保存場所とその別名へ由来の合併を伝える。
精度の高いフィールド単位解析やライフタイム注釈を追加することは前提にしない。

### 4. 読み取り経路からの変更権限の取り出し

これは新しい領域保護ではなく、新仕様そのものの検査である。

- 直接の書き込み、変更可能な参照・スライス引数への引き渡し、変更するメソッド呼び出しを拒否する。
- 再借用、参照を含む値のコピー、配列・合併・ジェネリクス、動的参照を介して権限を復元できないようにする。
- 読み取り専用のレシーバーから変更可能な参照を返す既存の拒否も、今回の移行では維持する。
- `.bytes` などのビューを通じて、タグ・参照・配列記述子のバイト列を不正に書き換えられないか確認する。
  文字列ビュー等に内部データの不変性を前提とする処理があれば、別名からの変更を含めて検証する。

### 5. コード生成・外部境界・スレッド

- `src/llvm.c` と `src/ranges.c` を確認し、`read^` だけを根拠にした値の不変性・別名不存在の仮定を置かない。
  LLVM の属性は意味ごとに確認する。`readonly` 自体を、別経路からの変更もない保証と混同しない。
  現時点の検索では、一般の読み取り参照への `noalias`・`invariant.load` の付与は見つかっていない。
- 配列の長さや境界を再利用する最適化では、別名からの変更を跨ぐ証明が有効か確認する。
- `externC^` の読み取り指定は、その引数を通して書かないという契約にする。
  C の契約違反を R^ の検査だけで防ぐことは求めないが、別の変更可能な引数からの変更は正当なものとして扱う。
- スレッド間の独立したコピー・転送可能性・Channel の所有管理は維持する。
  `read^` の緩和を、通常の参照のスレッド間共有許可やデータ競合の許可に使わない。

## 実装順序

1. 上記 1〜3 の危険な操作を最小の回帰ケースにする。
   従来は読み取り保護で拒否されていたケースと、独立した寿命・縮小・型検査で拒否されるケースを分ける。
   実装上の不足があれば、保護の削除と同じ変更で補う。
2. 保護専用の root・状態・呼び出し間の競合解決を削除する。
   同居する構築時の書き込み禁止・参照フロー・静的状態・外部境界の検査は残す。
3. 読み取り参照の保存・返却を通常の参照フローへ統合する。
   変換したブロックの深さではなく、参照先の寿命で可否を決める。
4. 権限の伝播と推論・IR の整合を確認し、最適化あり／なしで実行結果を比較する。
5. mini_doom の該当引数を `read^` にし、`bounds` を `let^` に戻す。
   `patch(lumps[i].name[..])` を直接渡せることも確認する。
   呼び出し先に必要な `read^` 宣言を揃えるが、関数本体からの権限推論は追加しない。
6. `read_parameters.md` を新仕様へ書き直し、`arrays.md`・`design.md`・関連例と診断を揃える。
   保護スコープ由来の制約を記述している `inline_for.md` 等も更新する。

対象スイートは `read`・`slices`・`arrays`・`flex`・`fits`・`nil`・`dispose`・`closures`・
`dyn`・`generics`・`inline`・`ffi`・`threads` とする。関連する IR・最適化検査も実施し、
最後に全体の既存チェックを実行する。LSP の型判断と診断もコンパイラに揃える。

完了条件は、上表の許可・拒否が確認でき、mini_doom の二つの不便が解消され、
読み取り保護専用の処理が残らず、通常の参照の安全性検査が維持されていること。
実装後の検証結果と残る保守的な制限は、以下に記録する。

## 実装結果

- `ReadBorrow`・`ReadCall`、保護境界、呼び出し間の読み取り競合の伝播を削除した。
  読み取り参照の保存・返却も、通常の参照フローと所有者の寿命で検査する。
- 構築中の所有行への書き込み禁止は `mutation_check` に残した。
  静的状態・間接呼び出し・外部公開入口の検査は `flow_validate` に残した。
- 別引数からの構造体フィールドの変更後に、古い変種の絞り込みが残るケースを確認し、
  外部由来の root 同士が重なる可能性も考慮してパスの事実を無効化した。
- Disposable 選択肢をその場で取り出す際に読み取り属性が落ちるケースと、
  読み取り経路の参照フィールドを変更可能な動的参照へ変換できるケースを修正した。
- Disposable ユニオンの置き換えで内部参照を無効にする操作を、既存の無効化検査へ統合した。
  構造体・固定配列内のユニオンと、呼び出し・捕捉・静的状態を経由する操作も対象にした。
- 関数を経由した grow^ の Disposable 要素の除去にも、無効化の要約を適用した。
  関数内で異なる仮引数から取り出した内部参照は同じ領域を指しうるので、
  破棄・縮小時には外部由来の root 間の重なりも保守的に扱う。
- 参照フィールドの差し替えは既存の保存先の寿命検査と由来の合併で扱い、
  差し替え前にコピーした参照と、差し替え後に読み直す参照の実行結果を回帰テストにした。
- `read^` だけを理由とする不変性・noalias のコード生成は追加していない。
  既存の範囲最適化は変更を跨ぐケースを対象外にし、テキストのデコードは範囲と文字の妥当性を検査している。
- mini_doom は `patch(lumps[i].name[..])` を直接渡し、床生成の入力を読み取り専用にして、
  `bounds` を `let^` に戻した。検証用コピーではウィンドウ作成前に終了する分岐だけを挿入し、
  Freedoom E1M1 の読み込み・画像展開・床生成を実行した。
  結果は lumps 1220、pictures 709、sectors 182、lines 1175、floor triangles 1366。
- mini_doom と mini_minecraft の完全なソースをビルドし、Minecraft の `--test` も通過した。
  Doom の描画・操作の確認は今回の検証には含めていない。

残る制限は、スコープ単位・オブジェクト単位の保守的な無効化検査、
必要な要約を使えない動的呼び出しの制限、参照フロー・無効化要約の既存の上限である。
65 個の読み取り引数だけを持つ呼び出しは許可するテストを追加した。
ライフタイム注釈・一般の非重複解析・append^ は追加していない。

検証結果:

- Release ビルド成功。
- `ctest --test-dir build -C Release --output-on-failure`: 全26スイート成功。
- `tests/read.py --all-opts`: 131件成功。実行ケースを `-O0`・`-O2` の両方で確認。
- `git diff --check`: 成功。
- `.rhat-ls/rhat.exe` にも同じビルドを配置済み。実行中のサーバーへの反映は再起動時。
