# 合併型とニル伝播

## 型と配置

型注釈に `T | nil^` と書くと、T または不在を保持します。
`nil^` は単位型でも値でもあり、整数のゼロ、`false^`、空文字列とは区別します。

```rhat
var^ count:i32^ | nil^ = nil^
count := 12
let^ read=f^ value:i32^ | nil^ ->i32^ { value ?? 0 }
```

無名の合併型は選択肢の集合で同一性を決めます。順序と重複は問いません。
`i32^ | nil^` と `nil^ | i32^` は同じ型です。無名の合併型同士は平坦化します。
`def^ Result = i32^ | nil^` のような名前付き合併型は従来どおり公称型で、
同じ選択肢の別宣言とは暗黙に変換しません。名前付きと無名の間では、
変換元の全選択肢が変換先に含まれればタグを付け替えてコピーできます。
名前付き合併型そのものを別の合併型の選択肢にした場合は、入れ子を保ちます。
ただし、既に nil を直接含む型への `| nil^` の追加は、元の型のままです。

`&T | nil^` は「参照または不在」、`&(T | nil^)` は「不在になり得る値への参照」です。
`(i32^ | nil^)[3]` は各要素が不在になり得る固定長配列です。

配置はタグと最大ペイロードを持つインラインのタグ付き共用体です。
合併型自体のためのヒープ確保はありません。参照と nil の組も現段階では同じ表現を使います。
選択肢に所有領域を含めることは引き続き禁止します。
伸長配列を任意にする場合は `&i32^[>..] | nil^` のように参照を保持します。
参照・スライスを含む合併型にも既存の寿命検査を適用します。

## 存在判定と絞り込み

`value?` は nil 以外なら `true^` を返します。`0?`、`false^?`、`""?` はすべて真です。
参照値自体は常に存在します。参照先の不在を調べる場合は `(*ref)?` と書きます。

```rhat
var^ value:i32^ | nil^ = 12
if^ value? {
    print(value + 1)
else^:
    print("absent")
}
```

直接の変数に対する存在判定、nil との等値・不等値比較で分岐内の型を絞り込みます。
`!`、`and^`、`or^` とループ条件でも、成立が保証される経路で適用します。
再代入や参照を通じた変更が可能な呼び出しで、対応する絞り込みを取り消します。
ループの次の反復でも保証できることを検査します。

## ニル伝播と代替値

```rhat
def^ Point { self^{ x:i32^=0 } }
let^ point:Point | nil^ = Point{x=42}
print(point?.x ?? 0)

var^ items:i32^[2] = [10,20]
let^ view:&i32^[2] | nil^ = &items
print(view?[1] ?? 0)
```

`?.` と `?[]` は受け手が不在なら、その後の後置連鎖全体を省略して nil を返します。
添字式やメソッド引数も評価しません。メソッドが手続きなら返り値は引き続き void です。
非 nullable な受け手にも使えます。

保護されるのはその連鎖です。途中のフィールド自体が nullable なら、
`root?.child?.value` のように改めて `?` が必要です。
括弧は連鎖を区切りません。別変数への束縛は区切ります。
存在する配列への範囲外アクセスは、従来どおり実行時エラーです。

`left ?? fallback` は左を一度だけ評価し、nil の場合だけ右を評価します。
左には nil を含む型が必要です。優先順位は単項演算より低く、通常の二項演算より高く、左結合です。
`base + value ?? 0` は `base + (value ?? 0)` を意味します。

合併型から取り出したインラインの構造体・固定長配列はコピーです。
その一時コピーのフィールドへの参照や、変更を伴うメソッド呼び出しは許可しません。
元の値を変更する場合は `&Point | nil^` のように参照を選択肢にします。
これにより、タグの変更によって既存の参照が別の型の保存領域を指すことを防ぎます。

## 条件付き代入

`target ?:= value` は、代入前の target が存在するときだけ代入します。
不在の値を埋める演算ではありません。左辺の場所は一度だけ求め、無効な右辺は評価しません。
非 nullable な左辺では通常の代入と同じです。

```rhat
var^ n:i32^ | nil^ = 1
n ?+= 2
n ?:= nil^
n ?:= 99  # 不在のまま
```

`?+=`、`?-=`、`?*=`、`?/=`、`?%=` も同じ条件で働きます。
存在時の型は単一の数値型である必要があります。
並列代入では、全左辺の場所・存在判定・必要な旧値を先に保存し、
有効な右辺だけを順に評価して保存した後、書き込みます。
`ref?.field ?:= value` のような左辺も、実体への参照を通じた場所なら使えます。
変更可能性、型、寿命の検査は省略される右辺にも静的に適用します。

関数値の保存・受け渡しが未対応のため、`?(` は今回導入しません。
既存の `.is(Type)` / `.get(Type)` と名前付きエラー型も引き続き使えます。
