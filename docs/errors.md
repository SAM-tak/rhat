# エラー値・伝播・捕捉

## エラーは値

`errordef^` の各種別は独立した公称型です。宣言名は種別の合併型となります。
成功値と同じく、タグ付き共用体の値として返します。ネイティブの例外機構は使いません。
構築は通常の構造体と同じ `Error.Invalid{}` です。エラーの合併は `for^ r { when^ fits^ Error.Invalid: ... }` で受けられ、式形で `other^:` を省くなら全種別を尽くす必要があります（[網羅](syntax.md#パターンマッチの網羅)）。構築接頭辞の `error^` は廃止しました。
エラーかどうかは `errordef^` の宣言元の型で決まり、構築の綴りには依存しません。
具体的な種別型が期待される位置では `{}` も使えますが、合併型の文脈から裸の `{}` で
エラー種別を暗黙に選ぶことはしません。その場合は種別名を明示します。

```rhat
errordef^ Error { Invalid, Missing }
let^ read=f^ n:i32^ ->i32^ | Error.Invalid {
    if^ n<0 { return^ Error.Invalid{} }
    return^ n
}
```

## 付随情報と生成位置

種別の本体は `def^` と同じ形で、フィールドは `self^{ ... }` に、メソッドはその外に書きます。

```rhat
errordef^ ParseError {
    Syntax {
        self^{ at:i64^ = 0, near:string^ = "" }
        message = f^ self^ -> string^ { self^.near }
    },
    Eof,
}
return^ ParseError.Syntax{ at = 3, near = s }
return^ ParseError.Eof{ message = "no input" }
```

どの種別も次を持ちます。宣言に書く必要はありません。

- `message()`: 表示用の文字列。既定では構築時に `message = "..."` で与えたリテラル、省略すれば種別名
  （`ParseError.Eof`）を返します。種別ごとに上書きでき、宣言したフィールドから文字列を返せます。
- `source:string^`・`line:u32^`・`column:u32^`: その値を構築した式の位置。コンパイラが自動で記録します。
  `source` は標準ライブラリなら `std/text.rh` の形、それ以外はコンパイラに与えたパスです。

ハンドラ側は種別ごとの違いを知らずに `it^.message()` で表示用の文字列を得られます。
腕が全部エラーの合併に対する `message()` は、保持している種別の実装をタグで選んで呼びます。
生成位置も合併のまま読めます。宣言したフィールドは種別ごとのものなので、`fits^` で絞り込んでから読みます。
`message`・`source`・`line`・`column` はフィールド名には使えません。

- エラー値が直接持つのは、構築した場所ごとの静的な記録（生成位置と message のリテラル）への参照 8 バイトと、
  宣言したフィールドだけです。フィールドのない種別は 8 バイトなので、`i64^ | E` のような結果は 16 バイトに収まり、
  LLVM の値のまま返します。フィールドを持つ種別は、それを含む合併だけを大きくします。
- そのため構築時の `message` は文字列リテラルに限ります。実行時の情報はフィールドで渡し、`message()` の上書きで表示に使います。
  `message()` の結果は借用の `string^` で、数値を埋め込むような文字列の組み立ては文字列補間とあわせて後続で扱います。
- 生成位置は構築式の位置です。`try^` で伝播しても、束縛してから `return^` しても変わりません。
  エラーを作る補助関数を経由すると、その関数の中の位置になります。
- 未処理のエラーと `panic^ it^` は、`message()` の結果と生成位置も表示します:
  `R^ runtime error at line 6: unhandled error ParseError.Eof: no input (raised at a.rh:9:27)`

L^ はエラー値に生成位置を刻まず、`std.debug.traceback()` を `message` に書く扱いです（04 の 11 章、05 の M4）。
トレースバックの機構を持たない R^ は、構築位置を静的に記録します。

エラーを返す関数を呼んだだけでは、制御は移りません。`fits^` とナローイング、
値マッチで値として扱うこともできます。

## 前置 `try^`

`try^ expression` は対象を一度だけ評価します。成功ならエラーの選択肢を除いた値を返し、
エラーなら囲む `catch^` 節へ移ります。対応する節がなければ、現在の関数からそのエラーを返します。
エラーを含まない型に対しては、そのままの値となります。

```rhat
let^ increment=f^ n:i32^ {
    return^ try^ read(n)+1
}
```

返り値の型を省略した関数には、伝播するエラーを含めて型を推論します。
明示した返り値型は、処理されないエラーをすべて受け入れる必要があります。
エントリーファイルのトップレベルには呼び出し元がないため、そこから出た未処理エラーはランタイムが
`R^ runtime error at line N: unhandled error E.Bad` のようにエラー種別名を表示し、終了コード 1 で終了します。

`try^` は単項演算子と同じ優先順位です。式全体を対象にするときは `try^ (expression)` と書きます。
エラーだけの値に対する `try^` は通常経路へ戻らず、`catch^ try^ it^` のような再送出にも使えます。

## 二項 `catch^`

```rhat
let^ value=read(-1) catch^ 0
let^ selective=read(-1) catch^ if^ it^ fits^ Error.Invalid: 0 el^: try^ it^;
```

左辺を一度だけ評価し、成功ならその値を、エラーなら右辺を評価した値を返します。
右辺は遅延評価され、読み取り専用の `it^` が捕捉したエラーを表します。
外側の焦点は `it^^` で参照できます。左辺にエラーの選択肢がなければ診断します。

優先順位は `??` と同じで、通常の二項演算子より高く、左結合です。
`read(-1) catch^ 2+10` は `(read(-1) catch^ 2)+10` となります。
右辺全体を代替値にするには `read(-1) catch^ (2+10)` と書きます。
右辺は値を作る式です。文を並べる場合や `return^` する場合は節を使います。

## ブロック末尾の `catch^` 節

```rhat
do^{
    let^ value=try^ read(-1)
    print^(value)
catch^ Error.Invalid:
    print^("invalid")
catch^:
    print^("other error")
}
```

`do^`、関数・手続き、`if^`、ループの本体末尾に書きます。
型付きの腕を記述順に調べ、最初に適合した腕だけを実行します。
フィルターにはエラー種別またはその合併型を指定します。
型なしの `catch^:` は一度だけ、最後に置けます。どの腕にも適合しないエラーは外側へ伝播します。

腕内の `it^` は、その腕に適合するエラーの型へ絞り込まれます。
本体内で宣言した変数は腕から参照できず、ブロックの外側にある名前を使います。
腕は自身の節には捕捉されません。腕での `try^` は外側の節または呼び出し元へ伝播します。
その節へ移る可能性がある `try^` が本体になければ診断します。

`if^` の最初の条件は本体の外です。条件の失敗は外側の節へ渡ります。
波括弧内の `elseif^` 条件と各分岐の本体は、その `if^` の節の対象となります。
関数 `f^` の本体・各腕が一つの式だけの場合は、通常の `f^` と同様に暗黙の返却となります。

## `panic^`

```rhat
panic^ "not implemented"
let^ value=read(-1) catch^ panic^ it^
```

`panic^ 値` は文字列か、エラー値の種別名を `R^ runtime error at line N: panic: ...` として表示し、
終了コード 1 でプロセスを終了します。値は省略できず、`string^` かエラー値に限ります。
戻らない式なので、`catch^` の右辺や腕にも置けます。後続のコードは到達不能として扱います。
`f^` の中でも使え、`catch^` / `try^` では捕捉できません。所有領域の巻き戻しは行いません。

## ループと保存領域

ループの節は `main^` の後、`last^` / `epilog^` の前に置き、各反復の本体だけを捕捉します。
腕から通常終了すると更新・次の反復へ進みます。`break^` / `next^` / `return^` も使えます。
`prolog^` / `pre^` / `first^` / `last^` / `epilog^` とヘッダー・更新の失敗は、
ループ本体の節を通らず外側へ渡ります。

節への移動とエラー返却の経路では、抜けるスコープの所有領域を逆順に巻き戻します。
初期化途中の所有変数も対象です。呼び出し元の返却先へ構築中に失敗して関数内の節へ移る場合は、
返却先スタックの保存位置を復元してから腕を実行します。
参照寿命検査と、全経路でのデータスタック所有者・回収の対応検証は維持します。

## 現在の範囲

- 共通の `error^` 型、`localerrordef^`、原因連鎖 `cause`、`message()` での動的な文字列の組み立ては未対応です。
- `with^`、`finally^`、エラー値の未使用追跡は追加していません。
- メモリ予約失敗や境界違反など、既存ランタイムの致命的診断は捕捉対象になりません。
- エラーだけの名前付き合併型は結果型の選択肢にできます。
  一方、成功とエラーが混在する名前付き合併型をさらに別の合併型の腕にした場合は、
  外側の他の腕を除外する型判定で内側の合併型へ絞り込み、名前へ束縛してから
  `try^` / `catch^` を適用します。

## 所有値を含む合併

伸長配列のような所有値も合併の選択肢にできます。失敗しうる処理が所有値を返すとき、
出力の受け先として `ref^ grow^ T[]` を渡す必要はありません。

```rhat
errordef^ IoError { Missing }
let^ read = p^ path:string^ -> grow^ u8^[] | IoError.Missing {
    if^ !exists(path) { return^ IoError.Missing{} }
    var^ bytes:grow^ u8^[] = []
    ...
    return^ bytes
}
var^ data = try^ read("a.txt")       # 呼び出し元へ伝播
let^ text = read("b.txt") catch^ grow^[0]
let^ found = lookup(key) ?? grow^[]   # -> grow^ T[] | nil^ の場合
```

- 合併は固定長の値で、所有値の選択肢はその記述子を中身に持ちます。データは合併を持つ束縛のデータスタックにあり、
  回収はタグに関係なくそのスタックを戻すだけです。
- 所有値の選択肢は、合併の中身に直接構築します。すべての `return^` が同じローカルを返す場合と同じく、
  そのローカルを最初から呼び出し側の構築先に置きます。ほかの選択肢を返す `return^`（エラー・`nil^`）が混ざってもかまいません。
- `try^`・`catch^`・`??` の対象が所有値を含む合併なら、対象を受け取り先のデータスタックに構築し、
  成功値はコピーせずに受け取り先へ移します。`catch^` と `??` の代替値も受け取り先に構築します。
- `fits^` で絞り込んだ束縛は、合併の中身をそのまま使います（`v.push(1)` など）。別の束縛へのコピーは、所有値のコピーとして拒否します。
- 失敗の前に途中まで作ったデータは、受け取り先が回収されるまでデータスタックに残ります。
