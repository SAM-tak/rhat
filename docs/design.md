# R^ 0.1 の実装規則

## 処理の流れ

```text
ソース
  → 字句解析・構文木
  → 定義・関数の名前登録
  → 公称の合成関係、抽象メンバの充足、配置
  → 呼び出しごとの具体化、本体の型・アクセス・効果・寿命検査
  → 型付き中間表現（具体的な保存場所・構築先・領域の回収）
  → テキスト LLVM IR
  → Clang によるオブジェクト生成・リンク
```

検査と中間表現の構築は具体化時に同じ走査で行います。LLVM IR の出力は、全検査の成功後です。
無効なプログラムについて LLVM の型検査や実行時の型判定に処理を委譲しません。

`src/front.c` は構文木、`src/check.c` は本体からの引数型推論・呼び出し形の検査・返り値型推論・式の型問い合わせ・マッチの網羅検査、
中間表現の構築は次の5つに分かれます。

- `src/types.c`: 型の構築・部分型・合併とエラー型の計算・def^ と enum^ の合成・配置。
- `src/sema.c`: 値と IR の基本操作、絞り込みと借用の事実、呼び出しの選択、式の構築。
- `src/statements.c`: 文・ループ・代入・catch^ 節、関数単位の構築（`instantiate`）と `analyze`。
- `src/errors.c`: エラー値の判定・梱包・伝播、`try^`・`catch^`、`message()`、未処理エラーでの終了。
- `src/text.c`: 組み込みの `char^`・`string^`・範囲、`write_text`・`tostring`、文字列補間。

`src/sema.h` は型推論と IR 構築で共有する状態・フロー操作と、上の5つの間で使う関数を宣言します。
`src/llvm.c` は LLVM IR と中間表現ダンプ、`src/main.c` は CLI と Clang の起動を担当します。
`runtime/rhat_runtime.c` は OS 領域、入出力、境界・除算・assert の検査です。

## トップレベル実行

トップレベルでは通常の文、def^、関数・手続きの宣言を混在できます。
宣言を登録した後、実行文をソースに書かれた順番で実行します。
main という名前に特別な意味はなく、main 関数は必須ではありません。
空ファイルや宣言だけのファイルは、何も実行せず正常終了します。

トップレベルの実行文は、暗黙の p^ として通常の型・効果・寿命検査を受けます。
そのローカル値がファイル実行中の状態を保持し、終了時に所有領域を回収します。
値なしの return^ はファイルの実行を終了し、同じ後始末を行います。
プロセス用のネイティブ main は LLVM バックエンドが生成します。
エントリーファイルのトップレベルは `p^ ...:string^` の本体で、`...` はコマンド引数です（[可変長引数とコマンド引数](variadic.md)）。
現段階では、名前付き関数からトップレベル変数を捕捉する機能はありません。
必要な値は引数で渡します。宣言は実行文より後ろに書いても呼び出せます。

0.1 はホスト x86-64 向けです。ポインタと i64^ のアラインメントを 8、128ビット整数を 16 とします。
任意ターゲットへのクロスコンパイルやパック配置は未対応です。

## 定義と合成

型同一性は `def^` の宣言で決まります。同じフィールド集合・配置を持つ二つの宣言は別の型です。
基底の列は左から右に処理します。新しいフィールドの席は末尾に追加し、
抽象フィールドの具体化は元の席に初期化子を与えます。型と公開範囲の変更はできません。
初期化子は最終的なフィールド順に評価します。未初期化の self へのアクセスは提供しません。
既定値がない数値・bool^・参照なしの固定配列はゼロ初期化し、構造体は各フィールドを構築します。
参照・文字列・スライス、および参照を含む配列には明示的な初期化が必要です。

具体メソッドの置き換えは `override^` を要求します。署名・f^/p^・mutable^ の契約を維持します。
異なる合成元から同名の具体メソッドが来た場合は、合成先で明示的に上書きします。
同じ型の公開された抽象フィールドは、別の合成元の具体フィールドでも満たせます。
抽象メソッドも、契約の一致する別の合成元の具体実装で満たせます。
具体フィールド同士の衝突は拒否します。独立した状態を二つ持つ場合は、名前付きの構造体フィールドで保持します。
同じ宣言元・同じ実装のダイヤモンド合成は重複排除し、経路による実装の食い違いは拒否します。
`super^` による前段呼び出しはまだありません。

抽象メンバが残る定義は構築できません。抽象定義は通常の引数の公称制約として使えます。
その関数は具体的な合成先の型で特殊化します。`Derived` を `Base` の保存形式に変換しません。
`Base` を合成したことは、独立した Base 部分オブジェクトの存在を意味しません。
具体型を知らないまま扱う必要がある場合は [ref^ dyn^ Base](dyn.md) を使います。
返り値と保存先には具体的な型を要求し、基底型への値の切り詰めを行いません。

メソッドを具体化するときの self は最終合成先の型です。アクセス権はメソッドの宣言元です。
そのため、A の private フィールドを読む A のメソッドは C 向けにも生成できますが、
C が新しく定義したメソッドにはそのアクセス権がありません。

## テンプレートと引数

`template^` は `template^f^` / `template^p^` として関数・手続きリテラルを修飾します。
`let^ name = template^p^ ...`、メソッドの `name = template^f^ ...`、
無名リテラルの直接呼び出しに共通の規則です。宣言の前に置く旧構文は受け付けません。
通常の `f^` / `p^` も、無注釈引数があれば同一モジュール内の呼び出しが渡す実型の並びで
本体を検査します。呼び出し形ごとに返り値も推論し、複数の形を合併して一つの署名にはしません。
メソッドと無名リテラルの即時呼び出しにも適用します。

具体化より前に、本体の型付きローカル変数・代入先・明示された返り値・既知の呼び先の引数・
構造体のフィールド・配列要素から要求を集めます。真偽条件は `bool^` を要求し、
数値演算は型の付いた相手側から幅を決めます。別名を介した要求も戻し、関数間の要求は
不動点まで伝えます。ここでは呼び出し元の実引数を参照しません。`x + 1` だけでは
幅は決まらず、メンバ名だけから公称構造体を選ぶこともしません。

一意に決まった引数型を制約として保存し、数値リテラルや裸の構築式の期待型にも使います。
合併型・基底型の制約でも、実引数の選択肢や派生型は維持して本体を具体化します。
`fits^`・ニル判定・`try^` / `catch^`・ニル伝播など、実型によって後続部分が検査対象から
外れる構文では、無条件に到達する手前までの要求だけを採用します。以降の要求は
具体化時に検査します。明示的な `template^` はこの事前推論の対象外です。
本体でも呼び出し形でも決まらない通常の定義には、型注釈か `template^` が必要です。

`template^` は、モジュール外からも具体化できる汎用定義であることを明示します。
公開する関数・公開型の公開メソッドでは、本体の要求だけで全引数が決まれば注釈を省略できます。
残る未確定引数には注釈または `template^` が必要です。公開署名を外部の呼び出し形から決めることはしません。
公開型の private メソッドは、宣言元モジュールの呼び出し形で検査できます。
通常の抽象メソッドの引数には注釈を要求し、既存の実装契約との一致も維持します。

公称型同士を同一視する処理はありません。注釈がある場合は通常の公称制約を維持します。
引数位置に期待型がなければ、裸の `{...}` から匿名の構造体を作ることはできません。
具体化のキーは関数宣言・self の実型・すべての引数の実型です。
0.1 は一プログラム 512 具体化を上限とします。

返り値の注釈がない関数・手続きは、具体的な引数型で本体を走査し、返り値型を推論します。
この型だけの走査と、型・効果・寿命を検査して中間表現を構築する走査を分けています。
呼び出しの循環では未確定の返り値を未確定のまま保持し、基底の返却値や演算の制約を種に
型が変わらなくなるまで推論します。根拠のない循環は診断し、任意の型で埋めません。
抽象メソッドを実装する場合は、その契約の返り値型を期待型として使用します。

f^ の本体が式一つだけなら、その式を return^ として扱います。複数文の最後の式や
p^ の裸の式にはこの規則を広げません。if^ 式は全分岐で値を持ち、最後の el^: と
終端のセミコロンを必須とします。条件付きの el^ を連ねることもできます。
LLVM IR では条件分岐を生成し、選ばれた節だけを共通の構築先に書き込みます。

無名の f^ / p^ をその場で呼び出せます。実行時の関数オブジェクトや環境の確保はせず、
通常の具体化した関数へ直接呼び出します。宣言が静的に決まる関数値の束縛・受け渡しに対応します。外側のローカル変数の捕捉は未対応です。
`this^` は自分の関数宣言を、`this^^` は字句的に一つ外側の関数宣言を指します。
ハットを増やすごとに関数の入れ子を一段ずつ外へ辿り、普通のブロックやループは数えません。
外側の関数の現在の実行フレームやローカル値を捕捉する機能ではありません。
`this^` によるメソッドの自己再帰は現在の self を引き継ぎますが、
`this^^` などで外側のメソッドを呼ぶ場合は受け手の参照も第一引数として明示的に渡します。
再帰でも確定した返り値型と引数型を検査し、通常のネイティブ呼び出しを生成します。
`this^^` による呼び出しも再帰成分の解析に含め、再帰呼び出しをまたいでローカル所有領域を保持するコードを拒否します。

固定サイズの引数は値渡しです。レコードや固定配列も呼び出し前にコピーし、
引数の評価は左から右です。所有領域を含む値はコピーできないため `ref^ value` で借用します。
メソッドの self は暗黙の参照です。動的な関数値や脱出する閉包はありません。

`let^` の保存領域は通常の代入・メンバ代入で変更できません。
`ref^ value` で参照を取得し、型は `ref^ T` と書きます。前置 `*` は明示的な参照先アクセスです。
メンバアクセス・メソッド呼び出し・添字アクセスは参照を一段自動で辿ります。
明示的に借用できるのは var^ の保存領域です。参照を格納した let^ から、その参照先を操作することはできます。
f^ は自分のローカル値を構築・変更できますが、借用先を変更できません。
f^mutable^self^ は self に由来する借用先の変更を許します。p^ は借用先を変更できます。
f^ から p^ や print を呼ぶことはできません。

## 数値演算と明示的な変換

整数の算術は型のビット幅でラップします。`bitand^` / `bitor^` / `bitxor^` は
同じ整数型を要求し、`*` / `/` / `%` と同じ優先順位・左結合です。前置 `bitnot^` は
その幅の全ビットを反転します。通常識別子の `bitand` などは引き続き宣言できます。

`value bitshift^ count` も同じ優先順位です。count は任意の整数型で、無注釈の整数リテラルは
i32^ として扱います。正なら左、負なら論理右シフトし、符号付きの value でもゼロで埋めます。
シフト数の絶対値が value の幅以上ならゼロです。i128^ の最小値を含め、絶対値の計算で
未定義動作を生じさせません。LLVM では実際のシフト数を幅未満にしてから結果を選択します。

`i32^(expr)` のように、組み込み数値型名の呼び出しで数値を変換できます。
引数は一つで、式を一度だけ評価します。整数間では狭めると下位ビットを保持し、広げると
変換元の符号に従って符号拡張またはゼロ拡張します。同じ幅の符号変更はビットを保持します。
たとえば `i8^(-1)` を u16^ に変換すると 65535、u8^ の 255 を i16^ に変換すると 255 です。
暗黙の混合型算術は追加しません。

整数から浮動小数点、および浮動小数点間は最近接・偶数丸めです。
f8^ への binary64 変換は binary32 を経由せず、二重丸めを避けます。
E4M3FN は無限大を持たないため、オーバーフローは NaN になります。
浮動小数点から整数はゼロ方向に切り捨てますが、変換前の値が
`[最小値, 最大値+1)` に入ることを先に検査します。符号なしの最小値はゼロであり、
負の小数も拒否します。NaN・無限大・範囲外は行番号付きの実行時診断です。
LLVM の範囲外変換に到達して poison を生成することはありません。

## 公称・無名の合併型

```rhat
def^ Num { self^{ value:i32^ } }
def^ Pair { self^{ left:u32^, right:u32^ } }
def^ Expr = Num | Pair
var^ values=grow^[Num{value=42},Pair{left=1,right=2}]
let^ value=values[0]
if^ value fits^ Num { print^(value.value) }
```

名前付き合併型自身は公称型です。同じ選択肢の組を持つ別宣言も別の型であり、相互に暗黙変換しません。
選択肢の型が期待する合併型に正確に列挙されているとき、値の構築・代入・引数・返却でタグを付けて格納します。
形の一致による適合も、合成された別の実型からのスライス変換も行いません。
選択肢は具体的な def^ 型、組み込み値型、参照、固定長配列、スライスです。
名前付き合併型では重複・不明な型・循環した値配置を拒否します。
入れ子の合併型も選択肢にできます。所有領域を含む選択肢も置けます（[所有値を含む合併](errors.md#所有値を含む合併)）。

`value fits^ Type` は適合を判定して bool^ を返し、分岐内で値の型を絞り込みます。
`if^ value fits^ Num { print^(value.value) }` と書けます。
型の判別・取り出し用の組み込みメソッドはありません。
型を証明せずに合併型の選択肢固有のメンバへアクセスすることはコンパイル時に拒否します。
`assert^(value fits^ Num)` も、正常に続く経路では型の証明になります。
取り出した構造体の private^ メンバへのアクセスは通常の規則に従います。
合併型自体から可変のペイロード参照は公開しません。値全体の再代入で選択肢を変更します。

配置は u32^ タグ、選択肢の最大アラインメントに揃えた保存領域、最大ペイロードの順です。
全体はタグと選択肢双方の自然アラインメントに丸めます。LLVM では整数チャンクの配列でペイロードを保持し、
bool^ の i1 や特定の選択肢の型で他の値のビットを失わないようにします。
構築時には保存領域をゼロ初期化して、タグと選択肢の値を書き込みます。
中間表現の `union.construct`・`union.is`・`union.project` はタグ番号と型を明示します。

参照を含む選択肢は通常の寿命検査に参加します。値のコピーと取り出しでも由来を保ち、
ローカルの所有者に束縛された参照を返すことや、長命な保存先へ書くことを拒否します。
値を別の選択肢で置き換えても、保守的な参照履歴は消去しません。
異なる選択肢を返す関数では、意図する合併型を返り値に明示できます。
型注釈の `T | nil^` とニル伝播、分岐による絞り込みは [合併型とニル伝播](nil.md) を参照してください。
`fits^` による適合判定・静的な判定の除去・型パターンは [fits.md](fits.md) を参照してください。

## 配置と構築先

固定長配列は LLVM の `[N x T]`、構造体は宣言順の LLVM struct です。
空構造体には一バイトの保存領域を与えます。パディングを含む実配置は x86-64 の自然配置です。
フィールド順・サイズ・アラインメント・オフセットは `.rir` に表示します。

すべての内部関数は、返り値がある場合に先頭の隠し構築先ポインタを受け取ります。
引数も内部 ABI では値を置いた場所へのポインタで渡し、関数入口で自分のスロットへコピーします。
R^ の通常の引数が自動的に参照渡しになるわけではありません。
LLVM ランタイムとの境界は明示的な C ABI のスカラー・ポインタだけに限定しています。
R^ 内の関数には内部リンケージを使い、16バイト以下の非所有値の引数と結果は
LLVM の値として直接渡します。整数・浮動小数点・bool・参照に加え、文字列・スライスや
小さい構造体・固定配列・列挙値も対象です。大きい集約値は従来の受け渡しを維持し、
所有結果は呼び出し側が用意した構築先に書き込みます。参照に一律の noalias は付与しません。

レコード・配列リテラルや関数の返り値は、指定された構築先へ書き込みます。
所有値の返却で、すべての return が同じ最上位ローカル名を返す場合、
そのローカルを最初から呼び出し側の構築先に結び付けます。所有値の移動コピーはありません。
別の所有変数を後から返却場所に移す操作は未対応です。

## 領域と寿命

伸長配列 `grow^ T[]` の保存表現は `{ data:pointer, length:u64, capacity_bytes:u64, high_water_bytes:u64 }` です。
組み込みの配列操作は `push`・`pop`・`clear`、長さは `len` という通常の識別子で提供します。
`push(value)` は新しい要素への `ref^ T` を返します。返り値を無視して追記だけを行うこともできます。
参照は配列自身と、その要素が参照する所有者の寿命に束縛され、後続の追記でもアドレスは変わりません。
参照の配列は `grow^ (ref^ T)[]` / `(ref^ T)[N]` と書きます。`ref^ grow^ T[]` は配列全体への参照です。
型の括弧で結合を指定でき、`ref^^ T` / `ref^ ref^ T` は `ref^ (ref^ T)` と同じ参照への参照です。
`ref^^^` 以降もハットの数だけ参照を重ねます。式でも同じ展開を行いますが、一時的な参照値への借用は認めません。
組み込み配列へのユーザーメンバ追加は認めないため、名前の衝突回避用の `^` は付けません。
コンパイラが所有値の生存期間と呼び出しグラフからデータスタック数を静的に決定します。
同時に生存する伸長配列は別のスタックを占有し、スコープを終えると番号を再利用します。
関数には隠れたスタック基準位置を渡し、借用した配列は元の所有者のスタックを使います。
所有値の返却先は初期化開始前に呼び出し側で確保し、呼び出し先が直接構築します。
`rhat check source.rh --stacks` で全体と各関数の必要数を表示できます。

生成プログラムは開始時に各スタックの 1 GiB と末尾の 1 MiB の保護領域を予約します。
物理メモリの一括確保ではありません。Windows は未コミット領域への読み書きを捕捉し、
最大 1 MiB 単位でコミットして再開します。既にコミットされたページの保護違反、
管理対象外の障害、実行アクセスは回復扱いにしません。POSIX は使用可能部分に
mmap の demand paging を使い、末尾をアクセス不能のまま保持します。
予約失敗・コミット失敗・スタック超過は診断して終了します。エラー値や例外は返しません。

伸長配列は `{ data:pointer, length:u64, stack:pointer }` の24バイトです。
スタック管理表は生成コードの静的領域にあり、配列の生成・スコープ終了では OS を呼びません。
push の通常経路は LLVM IR 内で書き込み・長さと先端の更新を行います。
添字の比較・アドレス計算も LLVM IR に直接出力し、範囲外の経路だけが診断関数を呼びます。
符号付きの負値を含む全整数幅を検査し、128ビット添字は長さ未満と証明した後にだけ64ビットへ変換します。
単純な i64^ の増加ループ（`i < upper`、`i := i+1`、直線的な本体）では、
入口のガードで全反復の添字範囲を証明した高速経路と、元の検査付き経路を生成します。
対象の添字は不変値・定数・ループ変数と加減乗算からなる式です。ガードは128ビットで区間を評価し、
添字計算の途中も含めて64ビットの符号付き範囲内かを確認します。折り返しの可能性があれば元の経路を使います。
呼び出し・伸縮・不規則な分岐を含む本体や、境界／ループ変数が別名参照から変更され得る場合は対象外です。
高速経路では不変の上限とデータポインタを保存して使います。空のループではガードを実行せず、
証明できない場合のエラー位置・それ以前の副作用は元の経路で維持します。
配列引数同士の重なりを禁止する情報は付けず、LLVM の通常の別名判定・自動ベクトル化を利用します。
push は残りバイト数と要素サイズを比較し、容量の割り算を行いません。
配列の構築後に長さを縮めていないことを制御フロー解析で証明できる箇所では、先端を直接更新します。
分岐は証明の積集合、ループは固定点を使います。呼び出し先が配列を縮める可能性も再帰を含めて伝播します。
縮小操作やその可能性がある呼び出しの後、借用先への追記では、従来どおり最大末尾を保持します。
ただし、プログラム全体に pop／clear／truncate がないと証明した場合は、借用先も直接更新できます。
各所有配列の構築時に論理末尾と先端は一致し、push／append／スコープ再利用だけではこの一致が崩れないためです。
これは外部エントリーや利用者が作れる配列記述子がない現在の閉じたプログラムに対する証明です。
縮小操作が一つでもあり得る場合は、この全体の証明を使わず、従来の局所的な解析に戻ります。
予約範囲と算術オーバーフローを検査し、大きな追記が保護領域を飛び越えることを防ぎます。
append は重なりを許す一括コピーです。ページのコミット判定は通常の追記経路にありません。
直前の命令で確定した文字列リテラルを u8^ 配列へ追記する場合は、容量を確認した LLVM の
コピーに展開します。不変のグローバル文字列と管理対象領域は重ならないため、この場合だけ memcpy を使えます。
一般のスライスや配列からの追記は引き続き重なりを許す memmove を使います。
一般の append も LLVM 内の alwaysinline ヘルパーで容量の検査・コピー・長さと先端の更新を行います。
要素数と残容量を比較してからバイト数を計算し、巨大な追記の乗算・加算のオーバーフローを防ぎます。
コピーは llvm.memmove、文字列リテラルだけは llvm.memcpy です。空の追記ではコピーを実行しません。
これらの intrinsic が最終的にネイティブのコピー関数になる場合もあります。
clear は LLVM IR で論理長だけを0にし、保存領域の先端は戻しません。
pop も通常経路では長さの検査・要素の読み込み・論理長の更新を LLVM IR に展開し、
空配列の場合だけ従来の診断処理へ渡します。値のコピーを長さの変更より先に完了します。
truncate も IR で負値と現在長を検査し、論理長だけを更新します。
slice は IR で開始位置・長さを検査して { data, len } を構築します。assert は IR の条件分岐です。
成功時にはこれらの C ランタイム呼び出しはなく、失敗時だけ行番号を診断関数へ渡します。

非所有値は伸長配列の管理情報を内包できず、配列の要素も非所有値に限られます。
参照から管理情報のフィールドや型の異なる記憶域へアクセスする操作もありません。
この型の制約を LLVM の TBAA に伝え、要素の更新による配列管理情報の再読み込みを抑えます。
管理情報の読み込みはフィールド単位で発行し、集約値の分解で別領域の情報が失われないようにします。
所有フィールドを含む構造体全体のコピーにはこの分類を付けず、両方に重なり得るものとして扱います。
参照引数同士が重ならないという指定は行いません。

f8^ の E4M3FN 変換も LLVM 内の alwaysinline な整数ビット演算です。
符号付きゼロ・非正規化数・NaN・最近接偶数丸めを扱い、f64^ からは f32^ を経由せず直接丸めます。
シフト幅を保証する分岐を先に置き、範囲外の LLVM シフトによる poison を避けます。

C ランタイムの公開関数は、スタックの開始・終了、出力、終了する診断関数に限ります。
ページフォールトのコールバックと OS の予約・コミット処理は C に残します。
旧配列操作・スライス構築・数値の検査／変換・旧整数除算ヘルパーは生成コードから参照しないため削除しました。
LLVM 組み込み処理の生成は src/llvm_builtins.c にまとめています。

スコープ終了では保存しておいたスタック先端を戻します。コミット済みページを保持し、
次の反復や関数呼び出しで再利用します。仮想領域を OS へ返すのはプログラム終了時です。
配列がスコープ内にある間は、論理長を縮めても初期化済み保存領域の最大末尾を維持します。

`truncate(new_length)` は長さを指定した i64^ の値まで減らします。負値や現在の長さを超える値は実行時診断です。
保存領域・初期化済みスロット・参照の由来を保持し、再追記で再利用できます。

`pop()` は末尾の要素を値として返し、長さを一つ減らします。空配列では行番号付きの実行時診断です。
`clear()` は長さをゼロにし、返り値はありません。いずれも可変の配列が必要であり、
f^ から借用先の配列を変更することはできません。
両操作は論理的な長さだけを変更し、保存領域・コミット済みページ・スロットの値を保持します。
既存の参照は領域の寿命まで同じスロットを指し続けます。後続の push がそのスロットを再利用すると、
既存の参照からも新しい値が見えます。添字は変更後の len に対して検査するため、非アクティブな末尾には添字でアクセスできません。
要素は所有領域を含まないため、pop/clear による要素の領域回収はありません。
ここまでは `grow^` の規則です。縮小で保存領域を返す `flex^` は [配列の種類](arrays.md) を参照してください。
参照の由来の履歴は消去しません。保持されたスロットへの別名参照を通じて、寿命検査を迂回することを防ぎます。
これはスロットの参照であり、世代番号によるオブジェクト同一性の保証は提供しません。

借用スライス `T[:]` は `{ data:pointer, length:u64 }` の16バイトの値であり、所有領域を持ちません。
固定長配列・伸長配列・スライス・文字列の添字に範囲を書いて作ります（[配列の種類・スライス・範囲](arrays.md)）。
`a[lo :: hi]` は hi を含まず、`a[lo to^ hi]` は hi を含みます。`a[lo ::]` / `a[:: hi]` / `a[::]` は省略した側を先頭・末尾とします。
境界は i64^ で、開始・終端の順に一度だけ評価します。`a[i :: i]` は空のスライスです。
負値・逆順・範囲外は行番号付きの実行時診断です。`to^` の終端の桁あふれも範囲外として検出します。
配列の一時値には使えません。配列を変数に束縛して、その保存領域の寿命を与える必要があります。
スライスのコピー・再スライス・関数の返却では、元の保存領域の由来を引き継ぎます。
ローカルのスライス記述子への依存は加えないため、借用引数の部分スライスを返せます。
スライスを構造体・配列に保存する場合にも通常の寿命検査を行います。

スライスは要素の保存場所への書き込み・可変参照の取得を提供しません。添字は値をコピーして読みます。
要素自身が参照である場合、その参照先まで凍結するものではありません。
元の配列の変更はビューからも見えます。ビューの長さは作成時の長さを保持し、
pop/clear/truncate 後も、保持された元のスロットを指し続けます。再追記でスロットを上書きすると新しい値が見えます。
文字列の添字とスライスは u8^ のバイト単位であり、後者の型は `u8^[:]` です。
任意のバイト範囲を string^ に変換する機能は追加しません。

伸長配列の `.append(view)` は、同じ要素型のスライスから要素をまとめてコピーし、返り値はありません。
u8^ 配列には string^ も渡せます。容量と寿命を検査し、参照を含む要素の由来は保存先に合併します。
参照を含まない値のコピーでは、コピー元の保存領域に寿命を束縛しません。
空の append は OS を呼ばず、複数ページを拡張する append は必要なページを一度にコミットします。
同じ配列のビューとの重なりも memmove で扱います。pop/clear 後の再利用では スタック先端を維持します。

複数の所有値は、同時に生存しない場合にデータスタックを共有します。
伸長配列の要素は、所有領域を含まない非空・固定サイズの値に限定します。
参照、文字列ビュー、参照を含む構造体や固定配列も扱い、構築・追記・添字代入のすべてで参照の由来を伝えます。
参照先の所有者が保存先より短命になる書き込みは拒否します。所有配列を含む構造体は末尾に一つだけ置けます。
その構造体の固定部分と配列要素を連続させる可変サイズ表現も未実装です。

参照には保存領域の由来（root）を追跡します。参照を含む構造体・配列のコピーや関数呼び出しでも由来を伝えます。
参照を含む要素を配列から読み出すときは、保存元の配列の寿命も引き継ぎます。
この保守的な制約により、実際の参照先が外側の所有者でも、短命なローカル配列を介した参照の返却を拒否する場合があります。
借用した保存領域への非 static な参照の書き込みは、引き続き拒否します。別の引数と保存先が同じ所有者に
由来することを表す一般的な関数間の寿命制約は、まだ提供しません。
ループは、外側の変数が保持する参照の由来が増えなくなるまで本体を再解析します。
次周で流入する所有者も検査し、試行時の IR を破棄して確定した本体だけを出力します。
再解析では保存場所・ラベル・root の識別を再使用し、領域の構築・回収を重複して出力しません。
内側スコープの参照を外側の保存場所へ書くこと、ローカルの保存場所への参照を返すことを拒否します。
引数から返る参照の由来は、参照を含む実引数すべての由来の和として保守的に扱います。
参照を含む値を借用先へ書く場合は、静的な参照だけを許します。
これは参照フィールドを介した間接的な所有者間の書き込みも含めて、呼び出し先で寿命を偽らないための制約です。
関数ごとの由来の上限は 64 です。履歴を合併するため、安全な再代入でも拒否する場合があります。

所有値の初期化前に中間表現の `stack.save` を置き、構築には `region.construct`、回収には `stack.restore` を使います。
IR にはスタック番号、構築先の所有者、呼び出し先の基準位置を明示します。
通常のスコープ終了とすべての return 経路に逆順の回収を挿入します。
呼び出し側が所有する返り値と借用した引数は、その関数では回収しません。
直接・相互再帰の同じ成分へ呼び出す際、ローカルの所有領域を保持するコードは拒否します。
所有値の初期化途中も対象です。再帰呼び出し前に内側スコープを終えるか、外部の配列を借用します。
所有値の返却をそのまま呼び出し元の構築先へ転送する再帰は許可します。
再帰の深さに応じてデータスタックを動的追加するフォールバックはありません。
固定サイズのローカル値・スライスはこの制限の対象外です。
実行時検査の失敗はプロセス終了です。通常の返却値としての公称エラー型は扱えますが、例外による非局所的な脱出はありません。

## 数値と実行時検査

組み込み型名の `^` は必須です。`bool` / `u8` / `string` などは通常のユーザー識別子です。
`def^ bool { self^{ value:bool^=true^ } }` のようにユーザーの型と組み込み型を区別します。
組み込み型そのものの名前（`bool^` など）は再宣言できません。

符号なし整数は u8^ / u16^ / u32^ / u64^ / u128^、符号付き整数は
i8^ / i16^ / i32^ / i64^ / i128^ を持ちます。型付き数値の暗黙の型変換はありません。
整数リテラルは期待する型に適合し、範囲外は拒否します。128ビットの範囲検査は
十進文字列で行い、ホストの i64 や double へ切り詰めません。表示も全ビット幅を維持します。
期待型が浮動小数点型の位置では、整数・浮動小数点リテラルをその型の定数として構築します。
無注釈の整数リテラルは i32^、浮動小数点リテラルは f64^ です。
整数の加減乗算はビット幅で折り返します。LLVM の nsw / nuw / noalias は推測で付与しません。
整数のゼロ除算、最小符号付き整数 / -1、同じ組合せの剰余は実行時診断です。
これらの検査は演算子の幅のまま LLVM IR に出力し、失敗経路だけが診断関数を呼びます。
浮動小数点から整数への変換も、NaNを拒否する順序付き比較で下限以上・上限未満を検査してから変換します。
境界は正確な2の累乗の定数です。列挙値の get もタグ一致を IR で検査し、失敗時だけ従来の診断を呼びます。
安全な定数の除数に対する不要な検査は LLVM が最適化できます。
固定・伸長配列の添字は負数を含めて境界検査します。
すべての整数型を添字に使用できます。u64^ / u128^ / i128^ の巨大な添字も切り詰めずに拒否します。

浮動小数点型は次の配置・形式です。通常の構造体・配列でも同じ幅を保ちます。

| 型 | バイト数 / アラインメント | 形式 |
| --- | --- | --- |
| f8^ | 1 / 1 | E4M3FN、指数4・仮数3ビット、最大有限値448、無限大なし |
| f16^ | 2 / 2 | IEEE binary16 |
| f32^ | 4 / 4 | IEEE binary32 |
| f64^ | 8 / 8 | IEEE binary64 |

丸めは nearest, ties-to-even です。f8^ の演算は f32 で計算して各演算後に E4M3FN へ丸めます。
f8^ の符号付きゼロ・サブノーマル・NaN を保持し、範囲を超えた演算結果は NaN とします。
有限値への飽和は行いません。次の仮想的な有限値480との中点464は偶数側の448へ丸めます。
f16^ / f32^ / f64^ の演算は LLVM の half / float / double として出力します。
無限大・NaN は通常の IEEE 演算規則です。浮動小数点の剰余演算は未対応です。

f8^ / f16^ / f32^ の十進リテラルは、正確に表せる隣接値の中点と十進桁列を比較して丸めます。
f64^ を経由する二重丸めを避け、丸め後に有限値を持てないリテラルはコンパイル時に拒否します。
アンダーフローはサブノーマルまたは符号付きゼロへ丸めます。f64^ のリテラルは strtod を使います。
表示は低精度型を double へ正確に拡張して既存の書式で出力し、演算精度・保存幅は変更しません。
128ビット整数の除算と半精度の補助演算には Clang の compiler-rt builtins をリンクします。
新しい整数の表示・除算検査と f8^ の補助関数は固定長のローカル値だけを使います。

f128^ は保留です。binary128 の保存・演算・入出力を実装するまでは、使用時に明示的に診断します。

## モジュールと分割コンパイル

```rhat
# lib/example.rh
module^ lib.example
public^ def^ Item { self^{ value:i64^ } }
public^ let^ twice=f^ x:i64^ ->i64^ { x*2 }
public^ let^ answer:i64^=40+2
```

```rhat
import^ lib.example
let^ lib=import^ lib.example
let^ item:lib.Item=lib.Item{value=lib.answer}
print^(lib.example.twice(item.value))
```

`module^` は先頭に一度、`import^` は最上位に書きます。取り込まれるファイルにはモジュール宣言が必要です。
通常形は完全修飾名、束縛形は別名を導入します。実行時の名前空間オブジェクトやテーブルは作りません。
共有する接頭辞は合流しますが、親や子の公開名、依存先が間接的に取り込んだ名前は自動的に使えるようになりません。
非公開名、名前の衝突、依存循環、宣言名と要求名の不一致は拒否します。

`public^` を付けた型・関数・テンプレート・定数だけを公開します。メンバの `private^` は従来どおり定義所有者に従います。
ライブラリのトップレベルは宣言だけです。定数はスカラー・文字列のリテラルとその演算に限り、
関数呼び出し、他の定数の参照、実行文、可変グローバルは許可しません。
注釈付き定数は使用先の期待型に左右されず宣言型を保ちます。エントリーファイルはトップレベルの文を実行します。

`a.b` は `a/b.rh` へ対応し、`--module-path DIR` の指定順、エントリーファイルのディレクトリの順で探索します。
`std.*` は同梱標準ライブラリ専用です。標準ライブラリとランタイムはインストール先の `share/rhat`、
開発ビルドではソースツリーから取得します。

依存全体を毎回解析し、名前解決後に型・寿命・構築先・再帰・必要スタック数を検査します。
テンプレートと合成の具体化は宣言元モジュールへ配置します。リンク名は宣言元と具体型から安定して作ります。
各モジュールを個別のLLVM IR・オブジェクトにし、スタック管理表と開始・終了処理はエントリー側だけに定義します。
モジュール内だけの関数は内部リンケージ、境界を越えて使う関数にはリンク可能な名前を与えます。
インポート側には必要な本体と補助関数の閉包を `available_externally` として供給し、LTOなしでもインライン化できます。

キャッシュキーは生成IR、コンパイラとClangの実体のSHA-256、最適化・ABI設定、ヘッダー探索に影響する環境から作ります。
ランタイムとOS乱数の橋渡しも独立してキャッシュします。完成したオブジェクトのSHA-256を別途保存し、再利用時に照合します。
Cランタイムは毎回プリプロセスし、ヘッダーとマクロの展開結果を含む入力からキーを作ります。
`--runtime` の差し替えや、そのランタイムが読み込むヘッダーの変更でも古いオブジェクトを再利用しません。
中断した生成物と破損したオブジェクトは再利用しません。生成IRへ変更が波及する依存モジュールも再コンパイルします。
既定は出力先の `.rhat-cache`、変更は `--cache-dir`、再利用の抑止は `--no-cache`、詳細表示は `--verbose` です。
解析結果の永続化と、ソースなしでのライブラリ配布は未対応です。
解析結果を再利用するための方針は [separate_compilation.md](separate_compilation.md) にまとめています。
C の関数は [externC^](ffi.md) で宣言して呼び出し、追加のライブラリは `--link-lib NAME` でリンクします。
`emit -o FILE.ll` と、`build` / `run` の `--emit-llvm FILE.ll` は依存全体を含む単一IRです。`build` / `run` は既定では `.ll` を残しません。
実際に分割ビルドでコンパイルしたIRはキャッシュに保存し、`--verbose` でパスを表示します。

## エラー値と標準乱数

```rhat
errordef^ Error { Invalid }
def^ Result = i64^ | Error.Invalid | nil^
let^ calculate=f^ x:i64^ ->Result {
    if^ x < 0 { return^ Error.Invalid{} }
    return^ x
}
let^ result=calculate(42)
if^ result fits^ i64^ { print^(result) }
```

各種別は独立した公称型、宣言名は種別の公称合併型です。値は `Error.Invalid{}` で構築します。
今回の種別は付随情報を持ちません。共通の `error^` 型、メッセージと原因連鎖は未実装です。
`try^`・`catch^` は [エラー値・伝播・捕捉](errors.md)、`fits^` は [適合判定と絞り込み](fits.md) を参照してください。
`nil^` は1バイトの単位型・値です。公称合併型は整数・実数・bool・文字列・nilも選択肢にでき、
既存の所有領域・参照寿命の制限に従います。型を名指す `is/get` で判定・取得します。
整数・実数リテラルには、対応する数値カテゴリの選択肢が一つだけの場合、その型を期待型として渡します。
同じ名前のトップレベル関数・手続きは、引数の型域が重ならない場合に多重定義できます。
型は関数・手続き型の交差 `&` で表します。メソッドの `overload^`・演算子の `op^`・
静的な関数値については [関数・手続きの交差型と演算子定義](overloads.md) を参照してください。

`std.sys` は `Error.OutOfMemory` を公開します。ランタイムの予約・コミット失敗時の診断と終了は維持します。
`std.random.Random` は非公開のu64状態を持つ値型です。GC・ヒープ確保・disposeは不要です。

| API | 結果・挙動 |
| --- | --- |
| `std.random.new(seed:i64^)` | `Random`。L^と同じseed混合・xorshift64*系列 |
| `std.random.new()` | `NewResult = Random \| Error.SeedUnavailable`。OSからseedを取得 |
| `r.reseed(seed:i64^)` | 明示seedで再開 |
| `r.save()` | 全64ビットを保持したi64状態。系列を進めない |
| `r.load(state:i64^)` | `LoadResult = nil^ \| Error.InvalidState`。ゼロを拒否 |
| `r.next()` | f64の `[0,1)` |
| `r.rangeint(lo:i64^, hi:i64^)` | `IntResult = i64^ \| Error.InvalidArgument`。両端を含む・棄却法 |
| `r.uniform(lo:f64^, hi:f64^)` | `RealResult = f64^ \| Error.InvalidArgument`。通常は `[lo,hi)` |
| `r.normal(mean:f64^, deviation:f64^)` | `RealResult`。Box–Muller、二つ目の標本は保持しない |
| `std.random.xorshift64(state:u64^)` | ベンチ用の従来の13・-7・17の純粋関数 |

不正引数と、rangeint/uniformの等しい両端、normalのゼロ偏差では系列を進めません。
uniformの等しい両端ではその値を返します。normalの極端な有限引数による結果のオーバーフローは許容します。
next/rangeint/uniform/normalとloadは `f^ mutable^ self^`、reseedは `p^ self^` です。
PRNGはR^、数学処理は `std.math`、`nextafter` とOS seed取得は [externC^](ffi.md) によるCの呼び出しで実装します。
暗号用乱数生成器ではなく、数学ライブラリの丸めが異なる環境間でnormalのビット一致は保証しません。

## 標準数学

```rhat
let^ m = import^ std.math
print^(m.sqrt(2.0), m.sin(m.pi / 2.0), m.atan2(1.0, 1.0), m.isnan(0.0 / 0.0))
```

`std.math` の関数は f64^ と f32^ のオーバーロードを持ち、引数の型で選びます。浮動小数点リテラルは f64^ を選びます。
実体は同じ幅の LLVM 組み込み関数（`llvm.sin.f64` など）で、定数引数の畳み込みと、命令または数学ライブラリ呼び出しへの変換は LLVM が行います。

- 定数: `pi`、`tau`、`e`（f64^）
- 平方根・三角・双曲線: `sqrt`、`sin`、`cos`、`tan`、`asin`、`acos`、`atan`、`atan2(y, x)`、`sinh`、`cosh`、`tanh`
- 指数・対数: `exp`、`exp2`、`log`、`log2`、`log10`、`pow`
- 丸め・符号: `floor`、`ceil`、`trunc`、`round`（中間値は0から遠い側）、`abs`、`copysign`、`fma`（一度だけ丸める）
- 判定: `isnan`、`isinf`、`isfinite`（R^ で実装）

組み込み関数は `public^ let^ sin = externLLVM^ llvm.sin.f64:f^ x:f64^ ->f64^;` の形で宣言します。
`externLLVM^` は標準ライブラリ（`std.*`）の `llvm.*` シンボル専用です。渡せる型と効果の規則は [externC^](ffi.md) と同じです。

## 文字列から数値への変換

すべての数値型が、型の側のメソッド `T.parse(s)` を持ちます。

```rhat
var^ disc:i64^ = 3
if^ (...).len > 0 {
    let^ parsed = i64^.parse(...[0])
    if^ parsed fits^ i64^ { disc := parsed else^: print^("usage: hanoi [DISCS]") return^ }
}
print^(disc)
```

`T.parse(s)` は文字列全体を読み、`T | std.text.Error.Invalid | std.text.Error.OutOfRange` を返します。
前後の空白は認めません。`import^` は要らず、エラー型のために `std.text` を見えない名前で読み込みます。
`try^`・`catch^`・`??` がそのまま使えます（`try^ i32^.parse(s)`）。

- 整数（`u8^` から `i128^` まで）: 省略可能な `+` / `-` と十進の数字だけを読みます。数字以外が混じれば `Invalid`、
  型の範囲を超えれば `OutOfRange` です。符号なしの型では `-0` だけが通ります。
- 浮動小数点（`f32^`・`f64^`）: ランタイムがNUL終端のコピーを作り、C の `strtod` / `strtof` で読みます
  （十進・十六進・`inf`・`nan`）。`f32^` は `strtof` で直接丸めます。絶対値が型の最大値を超えると `OutOfRange`、
  アンダーフローは0側に丸めた値です。
- `f16^`・`f8^` は `f64^` として読んでから型に丸めます。丸めた結果が最大有限値を超える値（`f16^` は 65520 以上、
  `f8^` は 464 以上）は `OutOfRange` です。
- `i32^("123")` のように、型名の括弧で文字列を変換することはできません（コンパイルエラー）。
  括弧付きの型名は数値の変換で、文字列を読むのは `parse` です。

## 検証

`tests/modules.py` はモジュール境界・オブジェクト再利用・乱数APIを O0/O2 で検証します。
`bench/check_modules.py` は全16種・48条件の従来のC++・Rust・R^の一致済み出力と照合し、
実際の分割IRで共有乱数関数がインライン化されることも確認します。速度の再測定は行いません。

`tests/run.py` は構文・意味検査での拒否、配置、中間表現の領域操作、生成した実行ファイルの出力、
実行時境界検査を確かめます。成功例と実行時失敗例は -O0 / -O2 の両方で Clang を通します。
名目的な不適合、template^ の不成立・private 違反、抽象メンバの不一致、局所参照の脱出、
所有値のコピー・再代入、効果違反、評価順と短絡評価を回帰テストに含めています。
`tests/nil.py` は無名合併型、ニル伝播の評価省略、条件付きの並列代入、
型の絞り込みとその無効化、参照の脱出拒否を O0/O2 で検証します。
`tests/fits.py` は静的・動的な適合判定、型パターン、比較連鎖、
安定なメンバ経路と別名経由の変更、生成IRの重複検査除去を O0/O2 で検証します。

## L^ の構文との対応

分岐、ループ各節、値パターンマッチ、代入、字句と、R^ で判断を残した要素は
[syntax.md](syntax.md) に整理しています。既存の静的合成 `def^ C : A,B` は維持し、
動的テーブルと `..` による定義合成は導入しません。
`tests/syntax.py` はこれらの評価順・多段脱出・初期化・所有領域の回収を検証します。

## 言語サーバーとの共有

`rhat lsp` は CLI と同じフロントエンドと実行ファイルを使い、名前解決・型推論・寿命・データスタックの検査を共有します。
`src/tooling.h` は任意のソースオーバーレイ、検査済みの束縛参照、回復可能な診断と割り当ての境界を定義します。
通常のコンパイルでは追加の解析記録を保持しません。
LSP の通信とクライアント向け機能は `lsp/` に置き、[言語サーバーの設計](lsp.md)にまとめます。
