# 文字列と文字（設計）

R^ の文字列と文字の扱いです。

## 実装の範囲

- 実装済み: `char^`、文字列リテラルの UTF-8 検査、`string^(bytes)` のキャスト、`s.bytes`、`s.slice(r)`、
  `s.decode(at)`、`s.count_chars()`、`s.chars()`、`s.find(t)`・`s.starts_with(t)`・`s.ends_with(t)`、比較。
- 実装済み: `std.text.Builder`（`append`・`append_char`・`text`・`clear`）、値の `write_text(out)`・`tostring()`、
  数値型の `T.parse(s)`（[文字列から数値への変換](design.md#文字列から数値への変換)）。
- 実装済み: 文字列補間 `$"...{x}...{y:%.2f}..."` と書式。
- 未実装: `split`・`trim`、確保しない反復（`each_char`・`char_indices`）、
  `std.text` の大文字・小文字変換と正規化。
- `externC^` の結果として受け取る `string^` は、まだ検査していません（C 側が UTF-8 を渡す前提です）。

## 方針

1. `string^` は **UTF-8 であることを保証するビュー** とする。境界で一度だけ検査し、あとは型の保証を信頼する。
2. ビューは文字数を持たない。文字列の位置は **バイトオフセット** で表す。位置は数えるものではなく、
   `find`・`decode` などの操作が返すものとして扱う。
3. `string^` 自身は `[]` と `len` を持たない。バイトとして扱うときは必ず `.bytes` を経由する。
4. 文字は専用の組み込み型 **`char^`**（Unicode スカラー値）で表す。
5. 文字は先頭から順に **解読** して読む。「x 番目の文字」を O(1) に見える形（`s.at(x)`）では提供しない。
   文字位置での任意アクセスが要るなら、`s.chars()` で `char^` の配列に一度だけ明示的に変換する。
6. 部分文字列や1文字分の文字列は、元の文字列を指す **ビュー** として得る。確保は起きない。
7. 書記素クラスタ（結合文字・絵文字の連なり）は言語の中心に置かず、ライブラリで扱う。

### UTF-8 の扱いの定石

方針は、UTF-8 の文字列操作で広く定着している次の定石に従います。

- 境界で検査し、内部では保証を信頼する（Rust の `str`）。
- 検索・分割・比較・連結・接頭辞や接尾辞の判定・空白の除去は、解読せずバイトのまま行う。
  UTF-8 は自己同期的で、文字の途中から始まる偽の一致が起きないので、バイト列のまま探しても文字の途中には当たらない。
- 位置は操作が返すバイトオフセットとして扱う（Rust の `find`、Swift の不透明な `String.Index`）。
- 文字が要るときは先頭から順に読む（`chars()`・`char_indices()`）。
- 「文字数」はほとんど要らない。保存や通信の上限はバイト数で、見た目の長さは書記素クラスタと東アジアの文字幅が要るため、
  どちらもスカラー値の数では正しくならない。
- 文字位置への任意アクセスが本当に要るなら、コードポイントの配列（UTF-32）に明示的に変換する（Go の `[]rune(s)`）。
  O(n) の代価を一度、読んで分かる場所で払う。

最後の定石は、「遅いと分かっていても、重要でない部分は初等的に書きたい」という要望への答えでもあります。
`s.at(i)` をループで使うと、見た目は O(n) なのに O(n²) になります。`s.chars()` なら代価は変換の一度だけで、
以後の `cs[i]` は O(1) です。

### L^ との違い

L^ の `string^` も UTF-8 だけを扱いますが、生成時に文字数を数え、`at(x)` と範囲は新しい文字列を作って返します。
R^ はこれを採りません。

- 文字数を持つとビューが 24 バイトになり、16 バイトを超えるため LLVM の値として受け渡せなくなります。
  範囲を取るたびに数え直しも要ります。
- 文字数が分かっても、UTF-8 では x 番目の文字の位置を先頭から読まずに決められず、`at(x)` は O(1) になりません。
- 新しい文字列を作るにはデータスタック上の確保が要ります。R^ の `string^` はビューなので、
  元の文字列の一部を指すビューで同じ用途を満たし、寿命は借用検査が保証します。

### 他のシステム言語

- Rust: `str` は UTF-8 を保証し、整数による文字の添字は持たない。範囲はバイト単位で、文字の途中なら panic する。
  文字は `char`（Unicode スカラー値）で、`chars()` で順に取り出す。本設計はこれに最も近い。
- Go: `string` はバイト列で UTF-8 を保証しない。`s[i]` はバイト、`range` で `rune`（int32）を取り出す。
- Swift: 文字は書記素クラスタ単位で、添字は不透明な `String.Index`。
- Zig: 文字列型を持たず `[]const u8` と標準ライブラリで扱う。

## `char^`

- 値は Unicode スカラー値、すなわち `0` から `0x10FFFF` のうちサロゲート `0xD800`〜`0xDFFF` を除いたものです。
  不正な値を持つ `char^` は作れません。
- 大きさ・配置は 4 バイトで、`u32^` と同じです。C の境界では `uint32_t` として渡します。
- 書き方:
  - `char^"あ"`: 文字リテラル。`char^` の直後に文字列リテラル（`'...'` の生文字列も可）を続けます。
    ちょうど1つのスカラー値でなければコンパイル時に拒否し、型は `char^` です。
    R^ は式の並置を関数適用にしないので、括弧の有無だけで変換と区別できます（`grow^[...]` と同じ前置の形）。
  - `char^(x)`: キャスト。`x` はちょうど1文字の `string^` か整数で、結果は `char^ | std.text.Error.Invalid` です。
    中身がリテラルでも `char^("あ")` はキャストとして同じ型を返します。範囲外の整数とサロゲートもこのエラーです。
  - `u32^(c)`: スカラー値を整数として取り出します。常に成功します。
- 演算: `=`・`<=>` とその比較（スカラー値の順）だけを持ちます。算術は持たず、必要なら `u32^` に変換します。
- `print^(c)` は UTF-8 で書き出します。
- `char^(...)` のキャストを使うモジュールには、エラー型のために `std.text` を見えない名前で読み込みます。
  利用者の名前空間には現れません。整数からのキャストは 64 ビット以下の整数に限ります。
- 単引用符 `'...'` は生文字列に使っているため、文字リテラルの構文には使いません。

## `string^`

### UTF-8 の保証

- 文字列リテラルは、コンパイル時に UTF-8 として正しいことを検査します。
  `\xHH` は `\x7F` 以下に限ります。それ以外のコードポイントは `\u{...}` で書きます。
  埋め込み NUL（`\0`）は UTF-8 として正しいので、今までどおり保持します。
- バイト列からの変換は検査付きのキャストです: `string^(bytes:u8^[:])` は `string^ | std.text.Error.Invalid` で、
  `char^(...)` と同じく、括弧付きの型名はエラーを返しうるキャストです。確保はせず、同じバイトを指すビューになります。
  `char^(...)` と同じく、使うモジュールには `std.text` を見えない名前で読み込みます。
- `externC^` から受け取った文字列は、`string^(bytes)` を通して初めて `string^` になります（未実装の検査を含む方針）。
  C に渡すときは今までどおりデータポインタ（と長さ）です。
- `exportL^` の境界では、L^ の文字列が UTF-8 を保証しているので検査は省きます。

### バイトとして見る

`s.bytes` は同じ記憶を指す `u8^[:]` のビューです（確保なし）。バイト数・個々のバイト・バイト範囲はこれで扱います。

```rhat
let^ size = s.bytes.len        # バイト数
let^ first = s.bytes[0]        # u8^
let^ raw = s.bytes[0 :: 4]     # u8^[:]
```

`string^` 自身は `[]` と `len` を持ちません。文字とバイトの取り違えを、書く時点で防ぐためです。

### バイトオフセットで操作する

いずれもバイトのまま動き、位置はバイトオフセット、部分文字列は元を指す `string^` のビューです。

- `s.slice(r:range^) -> string^`: バイト範囲 `r`（[範囲](ranges.md)）のビュー。端が範囲外か文字の途中なら、範囲外の添字と同じく終了します。
  端の検査は、端のバイトが継続バイト（`0b10xxxxxx`）でないことを見るだけなので O(1) です。
- `s.find(t:string^) -> i64^ | nil^`: 最初に現れる位置。
- `s.starts_with(t)`・`s.ends_with(t)`。`s.split(t)`・`s.trim()` は未実装です。
- `s = t`・`s <=> t`: バイト列としての比較。UTF-8 ではバイト順とスカラー値の順が一致します。

### 文字単位の操作

```rhat
let^ s = "aあ😀"
var^ at = 0
repeat^ while^ at < s.bytes.len {
    let^ c, next = s.decode(at)      # 文字と、次の文字のバイト位置
    print^(c, s.slice(at :: next))    # char^ と、その1文字分のビュー
    at := next
}

let^ cs = s.chars()                   # grow^ char^[]: 一度だけ O(n) で変換して確保
print^(cs[2], cs.len)                 # 以後は O(1)
```

- `s.decode(at:i64^) -> (char^, i64^)`: バイト位置 `at` から1文字を解読し、文字と次の位置を返します。
  `at` が範囲外か文字の途中なら、範囲検査と同じく終了します。`string^` は UTF-8 を保証しているので、それ以外の失敗はありません。
- `s.count_chars() -> i64^`: スカラー値の数。一度たどるだけの O(n) で、それを名前で示します。
- `s.chars() -> grow^ char^[]`: スカラー値の配列への変換。文字位置での任意アクセスやスライスは、この配列の上で行います。
  所有値なので束縛して使います（`let^ cs = s.chars()`）。
- 反復の約束（`for^ ... in^ ...`）が決まったら、確保せずに順に読む `for^ c in^ s.each_char()` と
  `for^ at, c in^ s.char_indices()` を `decode` の上に用意します。
- `s.at(x)` と、文字位置で切る `slice` は設けません。
- 文字の途中で範囲を切った場合にエラー値を返す版は設けません。範囲の端は `decode` が返す位置から得るのが通常で、
  途中を切るのは範囲外の添字と同じくプログラムの誤りだからです。
- 1文字分の文字列が欲しいときは `s.slice(at :: next)` のビューを使います。`char^` から文字列を作る操作は、
  書き出し先を受け取る形（下記）で提供し、`char^` を文字列に変換して返す関数は設けません。

## 文字列を作る

`string^` は借用ビューなので、文字列を新しく作るには所有する保存場所が要ります。保存場所は `grow^ u8^[]` とし、
`string^` はその上のビューとして得ます。

`std.text.Builder` は普通の値の型で、束縛ごとに自分の領域を持ちます。中身は非公開の `grow^ u8^[]` で、
追記の手段を UTF-8 を保つものに限るため、任意のバイトを追記できる素の `grow^ u8^[]` と区別します。

```rhat
import^ std.text
var^ out = std.text.Builder{}
out.append("x = ")
(42).write_text(ref^ out)
out.append_char(char^"!")
print^(out.text())           # x = 42!
let^ s = (0.1).tostring()    # 新しい Builder
print^(s.text())
```

- `append(s:string^)`・`append_char(c:char^)`: UTF-8 として追記します。`clear()` は空にします。
- `text() -> string^`: 組み立てた内容のビュー。寿命は builder の借用です。今は `string^(bytes)` と同じ検査を通します。
- 組み立てた文字列を返す関数は `-> std.text.Builder` と書けます。

### 値を文字列にする

数値・`bool^`・`char^`・`string^` は次の2つを持ちます（L^ の 14.17 の `tostring` にあたる）。

- `x.write_text(out:ref^ std.text.Builder)`: `x` を `out` に追記します。基本の操作で、確保は `out` の中だけです。
- `x.tostring() -> std.text.Builder`: 新しい Builder を構築先に作って `write_text` します。所有値なので束縛して使います。

どちらかを使うモジュールには、`char^(...)` と同じく `std.text` を見えない名前で読み込みます。

書式:

- 整数は 10 進。128 ビットも含みます。
- 浮動小数点は、読み戻して同じ値になる最短の表記です（`0.1` → `0.1`、`1.0 / 3.0` → `0.3333333333333333`）。
  指数が -7 以下か 21 以上のときだけ指数表記にします（JavaScript と同じ）。
  整数として読める綴りには `.0` を足し（`2.0`、`2500.0`）、NaN は常に `nan` です（L^ の 14.8 と同じ規則）。
  `f8^`・`f16^` は `f64^` に広げてから書きます。
- `bool^` は `true`・`false`、`char^` は UTF-8。
- `print^` の浮動小数点も同じ書式です。

### 文字列補間

L^ の 01 の 5.4 と同じく `$"..."` と書きます。穴は `{式}` か `{式:書式}` です。

```rhat
print^($"n = {n}, pi = {pi:%.2f}, hex {n:%04x}")   # print^ はそのまま表示する
out.append($"[{n:%5d}]")                         # Builder にはそのまま追記する
let^ s = $"x = {x}"                              # それ以外は新しい Builder を作る
print^(s.text())
```

- 書き方は L^ と同じです。`$` と `"` の間に空白は置けません。`{{`・`}}` で波括弧そのもの、
  テキストの中の単独の `}` は文字のままです。`$'...'` は補間しません（専用の診断で拒否）。
- 穴の中は普通の式です。括弧で囲まれていない最初の `:` から `}` までが書式で、
  `:` を最上位に含む式（if 式など）は括弧で囲みます。穴の中に文字列や別の `$"..."` も書けます（入れ子は 32 まで）。
- 穴は `write_text` で書きます。数値・`bool^`・`char^`・`string^`、`std.text.Builder`（その `text()`）、
  入れ子の `$"..."`（同じ Builder に続けて書く）を置けます。
- 値は使う場所で決まります。`print^` の引数なら一時の Builder に作って表示し、すぐ回収します。
  Builder の `append` の引数なら、その Builder に直接追記します。それ以外では新しい `std.text.Builder` を構築先に作るため、
  束縛して使います（`let^ s = $"..."`）。L^ の補間は新しい文字列を作りますが、R^ の `string^` は借用なので、
  書き出し先を受け手が決める形にしています。
- 使うモジュールには、`tostring` と同じく `std.text` を見えない名前で読み込みます。

### 書式

書式は L^ の 14.17 と同じく C の `snprintf` のものです。`x.tostring(fmt)`・`x.write_text(out, fmt)` と、
補間の `{x:fmt}` で使えます。

- 変換はちょうど1つで、数値の変換 `d i o u x X f F e E g G a A` に限ります。旗（`-+ #0`）・幅・精度を書けます。
  変換の前後の地の文と `%%` も書けます。
- `s p n`、`*`、長さ修飾子は書けません。長さは処理系が補います。
- 変換が値の読み方を決めます。`%d` 族は整数として（実数は切り捨て）、`%f` 族は実数として書きます。
  `%d` 族で書ける整数は 64 ビットまでです。
- 外れた書式、255 バイトを超える結果は実行時の誤りとして終了します。書式は数値にだけ書け、
  それ以外の値に書くとコンパイル時に拒否します。

## 標準ライブラリ（`std.text`）

いずれも Unicode の属性表を使い、Unicode のバージョン更新に合わせて表を差し替えます。

- 大文字・小文字: `to_upper`・`to_lower`。変換で長さが変わる場合がある（`ß` → `SS`）ため、文字列版は書き出し先の
  `Builder` を受け取ります。`char^` 版は1対1で対応する単純な変換だけを返します。
- 正規化: `normalize`（NFC・NFD・NFKC・NFKD、書き出し先を受け取る）と、正規化済みかを判定する `is_normalized`。
- 書記素クラスタ: 人が「1文字」と感じる単位（UAX #29）。`か` + 結合用濁点（U+304B U+3099）の `が`、
  地域指示記号2つの国旗 🇯🇵、結合子 ZWJ でつないだ家族の絵文字 👨‍👩‍👧（5スカラー値）、肌色修飾子付きの 👍🏽 などは、
  複数のスカラー値で1つの書記素クラスタです。カーソル移動・表示上の切り詰め・見た目の文字数に要ります。
  言語の中心には置かず、必要になった時点で `std.text` に境界を求める関数を加えます。

## 決定事項

- 文字列の位置は基本的にバイトオフセットで表す。`slice(r)` もバイト範囲。
- `string^` は `[]` と `len` を持たず、バイトは `.bytes` を経由する。
- `s.at(x)` は設けない。文字位置での任意アクセスは `s.chars()` の配列で行う。`count_chars()` は持つ。
- 文字の途中で範囲を切ったときは終了する。エラー値を返す版は設けない。
- `char^` の文字リテラルは `char^"..."`、括弧付きの `char^(...)` はエラーを返しうるキャスト。
